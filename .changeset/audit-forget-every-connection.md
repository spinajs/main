`forget(subject)` without a `source` on a table trail now erases the subject on every connection that holds the trail table (with the columns `seq`, `at` and `data_hash`), not only on the trail's own connection, where transactional events of other connections stayed unerased. It records an `erasure` event on the trail's connection and on each other connection where the subject has a row, with that connection's count (so running `forget` again writes a record whose write failed), so `verify` finds the record beside the payloads it explains. Every connection is looked at before anything is blanked; then each connection's erasure is recorded right after it was blanked, so a failure on one connection never leaves an earlier one blanked without its record. `AuditReader.redactEach(trail, subject, source?)` is new: an async generator that yields one `AuditRedaction` (`{ connection, redacted }`) per connection that needs its own record, which `forget` records before it asks for the next; by default it calls `redact` once and records on `source`. `forget` returns the sum. A connection that cannot be inspected fails `forget` with `AuditWriteFailed` naming it, before anything is blanked. `spinajs audit:verify` without `--source` now finds connections the same way, so a table of the trail's name without the trail columns is no longer verified. Erasure never blanks an earlier `erasure` record: `redact` on a trail table, an archive and the buffer skips erasure records (`kind: 'custom'` with `action: 'erasure'`, the pair reserved for `forget`; verify and the queue consumer use the same predicate), so forgetting a subject again keeps the first record's payload and count.
