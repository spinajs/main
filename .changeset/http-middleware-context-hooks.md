Route middleware hooks take one context object, and every framework reply goes through one reply pipeline. Breaking: `onBefore(req, res, route, controller)` becomes `onBefore(ctx: IMiddlewareContext)`, `onAfter(req, res, route, controller)` becomes `onAfter(ctx: IReplyContext)`, and `onResponse` is removed: use `onAfter` with `ctx.response`; a middleware that still defines `onResponse` fails the route registration with `RouteRegistrationException`. `onAfter` now runs for every reply of a matched route, before it is sent: the action's `Response`, an `@OnError` or error-map reply (with `ctx.error`), a `Response` an `onBefore` returned, and an `@Idempotent` replay. It runs inner first, in the exact reverse of the entry order (a route's middleware before the controller's), inside the action's AsyncLocalStorage context, and only for middlewares the chain entered. A throwing `onAfter` turns the reply into the error reply for its error (route `@OnError` at the `'after'` stage, `http.errors.handlers`, the error map); hooks already run are not re-run, and a throw on that error reply is logged. An `onBefore` may return a `Response` to answer the request without the later middlewares and the action. New `onFinish(ctx: IFinishContext)` runs once when the response finished or the client went away (`ctx.aborted`); the `onFinish` hooks of a request do not wait for each other. An `onBefore` answer that is not a `Response` fails the request with `UnexpectedServerError` naming the middleware. When an action wrote `res` itself, `onAfter` does not run and no 404 follows. `RouteMiddleware` extends the new `HttpMiddleware` base, which extends `AsyncService`; `IRouteInvocation` extends `IMiddlewareContext`. `Response` gains `data`, a `statusCode` setter, `headers` and `setHeader()`; headers set in `onAfter` win over `IResponseOptions.Headers`. `sendReply(req, res, response)` lets an `onAround` that does not proceed answer through the pipeline. An `@Idempotent` replay is a new exported `ReplayedResponse` whose `data` is the stored body; a data change an outer `onAfter` makes on it is sent, and headers `onAfter` hooks add are not stored for replays. `RouteTiming` now times error replies too. `@Accepts` mounts the named `AcceptsMiddleware`. An error raised after the headers were sent is logged and a cut-short reply drops the connection, instead of an unhandled rejection. `createActionHandler` loses its middlewares parameter, and `wrapMiddlewareAction` is replaced by `createBeforeHandler` and `createEntryHandler`. `JsonFileResponse` keeps its data and options in the `Response` fields.
