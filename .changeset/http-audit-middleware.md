New `Audit` route middleware: one `IAuditRecord` per request of a route, with the redacted URL, query and body, the status, the error of an error reply, the principal (`req.storage.Principal`, else `AuthnPrincipal`), the time and `aborted`, written once the response finished to the `AuditSink` service. The default `LogAuditSink` logs it on the `audit` logger; register an own `AuditSink` to store it elsewhere. A failing sink is logged on the `http` logger and never fails the request. Mount it with `@Middleware(Audit, options?)` or as `'Audit'` in `http.routes.middlewares`. `http.audit { methods, redact, includeBody, maxBodyBytes }` configures it, route options override it and add redact keys. Redaction is recursive and matches keys as case-insensitive substrings (default `password`, `token`, `secret`, `authorization`, `cookie`, `card`); a path segment holding a route parameter with a sensitive name is redacted in `url` too. An error's message is recorded only when it is not answered as a 500, cut to 200 characters.

`MiddlewareStage` gets a third value, `'beforePolicy'`: such a route middleware is mounted before the policy gate and entered first, so its `onAfter` and `onFinish` see a policy refusal (401, 403) as an error reply; the policies always run after it, so a refusal replaces an answer of its `onBefore`. `Audit` uses it, so policy refusals are audited. Code that switches over `MiddlewareStage` exhaustively must handle the new value.
