A controller-level `@SocketAccess(permission, { fields })` is recorded on the socket controller's manifest entry (`fields`, optional), read as a command's `fields` is: `'filter'` and `'filter-rows'` as written, a `fields` the build cannot read as `'filter'` with a `CMP001` note. `@spinajs/http-socket` applies it to every command without its own `@SocketAccess`, inherited ones included, and now the generated client types the result of such a command as `Redacted<T>` (a stream as `AsyncIterable<Redacted<T>>`) and AsyncAPI marks its reply redactable with the controller's permission; before, both described the full model. Client code that read a property of such a result without a guard no longer type-checks: check it for `undefined` first. A command with its own `@SocketAccess` keeps its own rule, with or without `fields`. A subclass without its own class `@SocketAccess` takes the nearest base's `fields`; a base read from a fragment built by an older compiler gives none, without a diagnostic, so such results stay typed `T` until that package is rebuilt. A command a subclass redeclares with `@Command()` alone now keeps the base command's `@SocketAccess` (permission and `fields`) and `@SocketPolicy` groups in the manifest, as `@spinajs/http-socket` keeps them. The socket stream hooks type the items of a redacted stream as `SocketStreamState<Redacted<T>>`, so the generated `client.socket.ts` type-checks for a filtered stream, by a command or a class rule. A manifest without class-level socket fields keeps its bytes and its hash.
