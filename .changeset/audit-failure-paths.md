Deferred writes: a batch that misses `audit.deferred.timeoutMs` is given up and never retried, and the next append to the same trail and connection waits for one still under way, so a call split at `maxBatch` keeps its order. An append that does not settle by the next batch's deadline blocks its trail and connection: their deferred batches are dropped unsent and logged as lost (with one warning per blocked target) until it settles, which is logged too. A failing logger or background flush no longer rejects a write or the process; the buffer-full warning is logged once per overflow, and a deferred `record` after dispose is written at once. An `AuditConfigError` raised by a store is never retried: confirmed writes rethrow it whatever `onFailure` says, deferred ones log it as a misconfiguration. `record` refuses `data` that cannot be written as JSON with `AuditConfigError`, `LogAuditStore` writes `data` as canonical JSON, and `canonicalJson` orders members as RFC 8785 does (by UTF-16 code units, integer-like keys included). `MemoryAuditStore.appends()` returns a copy.

An unknown key on a trail, in its `retry`, in `audit.hashKey` or in `audit.deferred` (a misspelt `onFailure` or `secret`, say) now fails the boot instead of being dropped silently.

The error for a trail whose store is `TableAuditStore` while no such store is registered now ends with a hint: install and import `@spinajs/audit-orm`, or set the trail's store to `LogAuditStore`.

A blocked target gives up its order after `audit.deferred.blockCeilingMs` (default 10 times `timeoutMs`, so 20000 ms by default): the service logs once at error level that its events may now be stored out of order relative to the held append, and writes again; a new stuck append blocks it again.

Confirmed writes have a deadline, `audit.confirmTimeoutMs` (default 10000): a write not done by then fails like any failed confirmed write (`AuditWriteFailed` on a `reject` trail, logged and dropped on a `continue` trail), its retries run inside it, and an append abandoned at the deadline is logged when it settles, at error on a `reject` trail, with `mode` and `onFailure` among the fields of every such line. The failure names the attempts actually made. A store may implement `AuditStore.joinsCaller(trail, connection)`: asked in the caller's async context, true makes a confirmed write append there instead of detached, so the record commits or rolls back with the caller's open transaction; such a write is tried once and has no deadline, and a store answering true must leave the caller's transaction usable when its append fails. A `joinsCaller` that throws reads as false and is logged once, unless it throws an `AuditConfigError`, which fails the write. `MemoryAuditStore.joinCaller(join)` sets it for tests.
