`@spinajs/http` opens an OpenTelemetry SERVER span per request (`TracingMiddleware`, a server middleware at Order -3 whose `onAround` keeps the span active for the rest of the request). When the request finishes the span is named `<METHOD> <route template>` (or `<METHOD>` when no route matched), with `http.request.method` (`_OTHER` plus `http.request.method_original` for a non-standard method, span name `HTTP`), `http.route`, `url.path` and `http.response.status_code`. A 5xx sets ERROR and records the error the reply answers as an `exception` event. A client that left before the status line was sent sets ERROR with `error.type` `aborted` and no status code; a streamed reply the client closed after its status line keeps that status and gets `spina.http.aborted: true`. A failure to start the span is logged and the request runs untraced. An inbound `traceparent` makes it a child of the caller. `RequestId` takes `req.storage.traceId`/`spanId` from that span and answers `traceparent` through the W3C propagator. `@spinajs/log` adds the `traceId`/`spanId` of the active span to every log line. The traceparent helpers of `@spinajs/log` (`parseTraceparent`, `newTraceContext`, `formatTraceparent`, `randomTraceId`, `randomSpanId`, `ITraceContext`) are deprecated and will be removed in 5.0; use `@spinajs/tracing`. In id-only mode (no span processor attached) and with tracing disabled, the `traceparent` response header carries trace-flags `00`: nothing is recorded, so a downstream parent-based sampler records nothing either.
