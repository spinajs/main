The runtime guard counts every column of a composite primary key. Before, it looked at the first key column only: on a model keyed `(order_id, id)`, `Line.where('order_id', 'o1')` passed as a single-object load and read every line of the order, other principals' lines included, without `AuthzConfigError` in `test` or a warning in `development`; a select that bound the whole key was flagged instead. Now a select is a single-object load only when each key column has one top-level equality joined by `AND`; a select that binds part of a composite key is a list, which the guard flags like any other unauthorized select. Bind the whole key (`Line.where('order_id', 'o1').where('id', 'l2')`) or read with `.accessible(permission)`. `get([...])` and `findOrFail([[...]])` on a composite key bind it inside a nested group and stay lists, as before. In production the guard is off, as before. The authz domain boot still refuses a registered `@AccessResource` class with a composite key. The guard rule also covers a subclass that extends a resource's key with `@Primary()`, which that check does not see, and queries that run before a domain booted.
