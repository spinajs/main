`TenantScopeMiddleware` (a query middleware, order 80): row-mode tenant isolation for the models declared with `@Tenant()`. It confines a select, update or delete built from a tenant model to the current tenant of `@spinajs/tenancy` and forces the tenant column on every inserted row. A statement on a tenant table with no tenant scope throws `TenantRequired`; an insert that carries another tenant throws `TenantMismatch`; in the all-tenants scope nothing is added and an insert must name its tenant. Inside a tenant, `NotSupported` refuses a query builder that does not go through the tenant model (no model, a model that is no tenant model, or another table, in any letter case) and, in a select of a tenant model, a populated to-one relation and a recursive query. Not covered yet: upserts; updates that write the tenant column or have no condition; a to-one populate of a tenant model from a model that is no tenant model; joins and sub-selects the caller writes; the static `Model.populate(relation, owner)`; raw SQL and `driver.execute(builder)` / `executeStream(builder)`, which skip the query middlewares; schema builders, a view over a tenant table included; enable the package only together with the next tenancy-orm release, which refuses the first of these.
