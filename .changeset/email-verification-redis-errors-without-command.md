"@spinajs/email-verification-redis": patch
---

Security: errors that leave the Redis email verification store no longer carry the arguments of the Redis command that failed. ioredis copies them onto its errors as `err.command` (`{ name, args }`), and onto each queued error of a transaction in `err.previousErrors[i].command`. For this store those arguments are the checked e-mail domain (in verdict keys, and in the list domains that `upsertEntries`, `removeEntries` and `replaceSource` write), stored meta values such as the list source URL that `DomainListSync` stores as `sync:<name>:origin` (with any token in that URL), and, when Redis refuses `AUTH` (`WRONGPASS`, `ERR invalid password`), the Redis password (with the ACL user name). ioredis rejects every queued command with that `AUTH` error, so it left every store method, and the store passed it to its own `error` line `Redis connection error` on every refused connection attempt. The framework's default `error` serializer writes only `name`, `message`, `stack` and `code`, so a default `@spinajs/log` setup wrote none of it. It was written by `util.inspect`, `console.error`, `JSON.stringify`, a logger that copies an error's own properties (pino's `err`), a `Log` implementation other than the framework's, an `error` serializer replaced with `registerSerializer`, or a `Log` call that passes the error as a format argument or under another field. If any of those applied while Redis refused a password, treat that Redis password as exposed: rotate it, and purge or shorten the retention of logs that hold it. The store now removes `command` from the error, and from each item of `previousErrors`, before it rethrows the error from `getVerdict`, `setVerdict`, `loadLists`, `listVersion`, `upsertEntries`, `removeEntries`, `replaceSource`, `getMeta` and `setMeta`, and before it logs a client `error` event. It rethrows the same error object: its class (`ReplyError`, `AbortError`, `Error`), `name`, `message`, `stack` and `previousErrors` stay as they were, so `instanceof ReplyError` and matching `READONLY` or `EXECABORT` in the message still work. Code that read `err.command.name` or `err.command.args` of an error from the store can no longer do that: branch on the message or the class instead.
