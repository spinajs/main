A holder that names nothing in the policy IR is reported as `AZV005`, an error, with an `unknown` verdict, so `spinajs authz:verify` exits 1. This covers the holder of `never`, the holders of `onlyVia` and the `except` list of `isolated`: a role that does not exist (`role:clrek`), a role on a type it is not granted on (`role:accountant@nosuch`, `role:clerk@org` for a role granted only on `$global`), a type or stored relation that does not exist (`nosuch#rel`, `org#auditor`), a permission written as a holder (`org#can_invoice_read`), an `anyone:` holder that names no permission of the type, another letter case (`Role:accountant`), the empty string, and a value that is not a string (`holder: ['role:accountant']` in a plain JavaScript assertions file, which answered `holds (exact)` before; `null` or a number crashed the command). A permission or `isolated` type that is not a string is `AZV006`. Before, `never` of such a holder answered `holds (exact)`, so a misspelt holder passed CI as a proof. `VerifyCode` and `Verdict.code` gain `AZV005`.
