New `RequestDeadline` server middleware (Order -0.3), off by default. With `http.deadline.enabled` every request gets an `AbortSignal` in `req.storage.signal` and its deadline (epoch ms) in `req.storage.deadline`, `http.deadline.ms` (default 30000) from when it runs. When the deadline passes, the signal aborts with a `TimeoutError` and a request nothing was sent for yet is answered 504 `{ error: { code: 'deadline_exceeded' } }` through the reply pipeline; the rest of the chain steps aside (server middlewares not reached yet, route middlewares, the action), a reply made later anyway is dropped and an error the action throws afterwards is logged at debug level. A route `onAround` waiting on `proceed()` gets the new `RouteAnsweredInPlace` (a `RouteClientGone` with `beforeRoute: false`), so an `@Idempotent` gate keeps its claim and a retry gets 409 instead of running the action twice. When the client goes away first, the signal aborts with an `AbortError`. `@Deadline(ms)` (`DeadlineMiddleware`) on a route or controller moves the deadline earlier, never later, and works without `RequestDeadline`. New `HTTP_STATUS_CODE.GATEWAY_TIMEOUT`.
