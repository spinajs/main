Security: a stored session whose `Expiration` is present but not an ISO 8601 instant (an empty string, `null`, `0`, `false`, a number) is now treated as expired: `restore` answers `null` and deletes the key as it does for an expired session, and listings leave it out. A warning names the subject of each such session. Before, an empty string, `null`, `0` or `false` read as "never expires", and a number such as `2099` read as that ISO year. Only an absent `Expiration` means a never-expiring session, which is what the store writes for one. At upgrade, existing sessions keep working: the store writes either an ISO 8601 instant or no `Expiration` at all. The one exception is a `null` that `save` wrote for a session whose expiration was an invalid luxon `DateTime` (every version since 2.0.481, the first one of this store, does so). Such a session used to never expire; it now ends, and its user signs in again. A stored `Creation` that is not an ISO 8601 instant now reads as the epoch. Before, under `SlidingCappedExpiration`, the next `touch` wrote the session back without an `Expiration`, and it then never expired.
