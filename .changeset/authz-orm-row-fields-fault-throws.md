`.withFields(permission)`, and `.accessible(permission)` under a `fields: 'filter-rows'` request, now fail the list with an `Error` when the field set of a group of rows is a `model_error` denial, instead of returning that group's rows with no readable field; an ordinary denial still gives its rows no field. `model_error` means the engine could not decide: an adapter or row-load failure, a check that threw, or an indeterminate model vote (a model that throws or times out, a `scope.<type>.*` attribute that resolves missing, a rebac `maxDepth`/`maxCalls` cut). A point check of such a row still answers a `model_error` deny (403 on an `@Access` route); the list answers 500. A field plan that faulted fails the list the same way. The exported type `RowFieldsRequest`: `none` is now the `none` plan's `DenyReason` instead of `true`; code that only tests it for truthiness reads the same, code that builds a request with `none: true` passes the plan's reason instead.
