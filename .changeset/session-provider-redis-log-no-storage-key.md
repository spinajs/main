Security: the store's log lines and its error about a stored session value no longer name the session. Before, they printed the session's storage key (the `sha256` of the session id in the cookie): `restore` threw `Session <SessionId> is not a JSON object`, and listings, revocations, `save`, `delete` and `touch` warned `Unreadable value of session <SessionId> skipped` and `Session <SessionId> has undecodable Data, read without its Data`. They now read `A stored session value is not a JSON object` (thrown), `A stored session value is not a JSON object; it is skipped` and `A session of <subject> has Data that does not decode; it is read with an empty Data`. `restore` still throws on a value that is not JSON, or whose `Data` does not decode, with the same error class (`SyntaxError`, `TypeError`), but with a fixed message (`A stored session value is not JSON`, `A session of <subject> has Data that does not decode`). The parser's own message quoted the stored value (V8 quotes a short value whole and the first ten characters of a longer one; the `Map` reader quotes a whole stored string), and the http error handler logs that message. Text only: what `restore`, the listings, `touch` and the revocations answer or throw is unchanged.
