Security: errors that leave the Redis email verification store no longer quote the arguments of a command Redis does not know. Redis 6.2 and later answer such a command (renamed or disabled with `rename-command`, or not supported by a proxy in front of Redis) with `ERR unknown command '<name>', with args beginning with: '<arg>' '<arg>' …`, quoting up to 128 characters of the arguments, and ioredis puts that reply into the error's `message` and into the first line of its `stack`. For this store the quoted arguments are the checked e-mail domain (in the verdict key of `getVerdict` and `setVerdict`, and in the list domains of a queued `SADD` or `SREM`, whose errors ioredis lists in `previousErrors` of the `EXECABORT` error), and the value `setMeta` stores, such as the list source URL that `DomainListSync` stores as `sync:<name>:origin`, with any token in that URL. The store now rewrites such a message to `ERR unknown command '<name>', with args beginning with: <redacted>`, in `message` and in the first line of `stack`, on the error it rethrows from every store method, on each item of that error's `previousErrors`, and on a client `error` event before it logs it. The command name stays. It is the same error object, with the same class (`ReplyError`) and `name`; every other message is unchanged. By reading the code (not by run), the unredacted message reached `warn` lines of `@spinajs/email-verification` under a default `@spinajs/log` setup: `Cannot read the cached … verdict` and `Cannot cache the … verdict` (that line names the domain in its own `domain` field as well), and `List … sync failed` when `setMeta` of the list origin failed (the list URL with its token). Code that read the arguments out of this message can no longer do that.
