"@spinajs/email-verification-redis": patch
---

Security: errors that leave the Redis email verification store no longer quote the arguments of a command Redis does not know. Redis answers such a command (renamed or disabled with `rename-command`, or not supported by a proxy in front of Redis) with `ERR unknown command '<name>', with args beginning with: '<arg>' '<arg>' …` (versions before 6.2 write the name and each argument in backticks), quoting up to 128 characters of the arguments, and ioredis puts that reply into the error's `message` and `stack`. For this store the quoted arguments are the checked e-mail domain (in the verdict key of `getVerdict` and `setVerdict`, and in the list domains of a queued `SADD` or `SREM`, whose errors ioredis lists in `previousErrors` of the `EXECABORT` error), the value `setMeta` stores, such as the list source URL that `DomainListSync` stores as `sync:<name>:origin` with any token in that URL, and, when the server does not know `AUTH` while a password is configured, the Redis password (with the ACL user name). The store now rewrites such a message to `ERR unknown command '<name>', with args beginning with: <redacted>` (the name keeps the server's quotes), also where the message appears in `stack`. It does so on the error it rethrows from every store method, on each item of that error's `previousErrors`, and on a client `error` event before it logs it. It is the same error object, with the same class (`ReplyError`) and `name`; every other message is unchanged. Before this change a default `@spinajs/log` setup wrote the unredacted message: the Redis password in the store's own `error` line `Redis connection error` (the default `error` serializer writes `message` and `stack`); the domain in the `warn` lines `Cannot read the cached … verdict` and `Cannot cache the … verdict` of `EmailVerification`, which also name it in their own `domain` field; and the list URL with its token in the `warn` line `List … sync failed`. The token was also printed by `spinajs email-verification:sync` and kept in the error of a failed `email-verification.list-sync` scheduler run, which `@spinajs/scheduler` stores with the run. If a server or proxy answered `AUTH` this way, treat that Redis password as exposed and rotate it. If it answered `SET` of a list origin this way, rotate that list token. In both cases, purge or shorten the retention of the logs and scheduler run records that hold it. Code that read the arguments out of this message can no longer do that.
