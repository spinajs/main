Journal keys are counted per branch. Durable calls made in one synchronous turn (`Promise.all`, `items.map(async ...)`) are siblings, and the code after each of them continues in a branch of its own, whose keys end in `@<branch>`. Same-name steps in such branches, and markers inside a branch, replay to their own recorded results whatever the timing of the non-durable work between them. Each journal row stores the number of its call in its branch (`Meta.call`), and a replay is checked against it, so a crash in the middle of a fan-out is no longer reported as non-determinism. Sequential code keeps its keys. Still required: a branch makes a durable call before any non-durable await, or uses per-item step names. The same holds for tasks run through a concurrency limiter, for branches wrapped in `AsyncResource.runInAsyncScope` or `AsyncResource.bind`, for branches that all await one durable promise, and for code that goes on after `Promise.race`. Otherwise a replay with other timing can hand one branch the result of another without an error, or fail the instance with `NonDeterminismError`, which is not compensated. Journals written by earlier 4.x pre-release builds do not replay.
