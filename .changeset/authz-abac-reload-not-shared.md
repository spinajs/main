`AbacModel` no longer hands a running policy reload to a check inside a transaction. With the ORM's savepoint queue, two checks of one request, one inside a nested `transaction()`, after an `invalidate()` or a failed reload over `DbPolicyStore`, waited for a reload whose `SELECT` was queued behind that check's savepoint: through `AuthzService.check()` both stalled until `modelTimeoutMs` (2 s by default) and denied with `model_error`, and a direct call of `evaluate` (or `preload`, `listPlan`, `summarize`) never settled. Now a check inside a transaction reads the stores itself and evaluates on its own read, which the model never keeps (it may hold rows the transaction rolls back, or an older snapshot); checks outside a transaction still share the reload. A store says which through the new optional `PolicyStore.inTransaction()`; `DbPolicyStore`, `MemoryPolicyStore` and `ConfigPolicyStore` answer it, and a store without it is treated as inside. Cost: one read of `authz_policy` per invalidation for the checks outside a transaction, as before, and one more read for each check inside a transaction while the reload is pending. A policy store of your own that does not implement `inTransaction()` makes every check that finds the policies behind read it for itself until the background reload lands; implement it (return `false` when its reads never join an ORM transaction) to share the reload again. A failed read still fails the check (`model_error`), never an empty policy set.
