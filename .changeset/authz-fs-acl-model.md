`OrmFileAclStore` writes `fs_acl` through the new model `FsAclRecord`, so the ORM write capture, and a history registered for the model, sees every file ACL change. The rows, their ids and the migrations are unchanged. `FsAclRecord` is on the ORM connection alias `authz-fs-acl` (`FS_ACL_CONNECTION`), which the package maps to the connection `authz.fsAcl.connection` names when the ORM boots, `default` when the key is not set: no configuration has to change. Breaking: `new OrmFileAclStore({ connection })` accepts only a name of the model's connection; a change of `authz.fsAcl.connection` after the ORM booted is refused instead of followed; an app's own `db.Aliases['authz-fs-acl']` must name the connection `authz.fsAcl.connection` names; and the table of `FsAclRecord` is checked at boot, so an app that imports the package without an `fs_acl` table runs the migration or sets `db.StrictTableCheck: false`; an app whose configuration does not load the package config files, or lives in a child container only, maps `db.Aliases['authz-fs-acl']` itself.

Fixed: `movePath` compares the filesystem name exactly (`SqlExpressions.equalsExactly()`), still in one statement for the whole path. Its condition on the name also moved the rows of another filesystem whose name differs only in case or trailing spaces, where the column's collation ignores them (MySQL `utf8mb4_bin` pads spaces, MSSQL ignores trailing spaces), so a grant could land on the wrong filesystem.
