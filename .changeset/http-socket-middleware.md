Socket commands run on `SocketMiddleware`, with the hooks of http's `HttpMiddleware`: `onBefore(ctx)` (a returned value other than `undefined` answers the command; a throw refuses it), `onAfter(ctx)` on the way out, inner first, before the outer middlewares and the ack (`ctx.result` writable, `ctx.error` on an error; a throw turns the outcome into that error), `onFinish(ctx)` once the reply is sent (a stream: once it ended) and the chain settled, with `ctx.aborted`, and `onAround(ctx, proceed)`, plus `Order`, `isEnabled(handler)` (once per command at startup) and `onRegister(handler, registration)`. Only entered middlewares get `onAfter` and `onFinish`. Every hook runs inside the call's AsyncLocalStorage store. New contexts `ISocketReplyContext` and `ISocketFinishContext`. New decorator `@UseSocketMiddleware(Type, ...options)` mounts a middleware on a socket controller or one command, resolved per command with `container.resolve(Type, options)`, at its own `Order`; a global middleware whose class the command declares runs once. Each command's chain is built at startup and kept as `handler.middlewares`; `SocketHandlerRegistry.Middlewares` lists the global ones. The built-in stages are socket middlewares with their names and `Order`s unchanged (`SizeStage`, `RateStage`, `ReadyStage`, `AuthenticationStage`, `LookupStage`, `PoliciesStage`, `ArgumentsStage` on `onBefore`; `InFlightStage`, `IdempotencyStage`, `OrderingStage` on `onAround`; `AccessFieldsStage` on `onBefore`/`onAfter`, enabled only on commands with a `fields` rule). Idempotency (500) and ordering (550) stay before the policies (600), unlike http's policy gate: a resend replays the outcome of the run it repeats even when a policy would refuse the command now.

Breaking: `SocketCommandStage` is removed. Register with `@Injectable(SocketMiddleware)` and move `execute(ctx, next)` to `onBefore`, `onAfter`, `onFinish` or `onAround(ctx, proceed)` (see "Migrating from SocketCommandStage" in the command pipeline guide). A middleware that still defines `execute` fails `SocketHandlerRegistry.build()` with an `InvalidOperation` naming the class, instead of being ignored. A subclass of a built-in stage overrides its hook instead of `execute`. Messages changed: "proceed() called twice by X" (was "next() called twice by X"), "middleware X refused the registration" (was "stage X refused the registration"), "a built-in middleware is missing" (was "a built-in stage is missing"). `onRegister` is no longer called for a middleware whose `isEnabled(handler)` is false. `SocketDispatcher` no longer holds the stage list (`Stages`); the registry does.
