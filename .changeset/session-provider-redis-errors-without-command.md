Security: errors that leave the Redis session store no longer carry the arguments of the Redis command that failed. ioredis copies them onto its errors as `err.command` (`{ name, args }`), and onto each queued error of a transaction in `err.previousErrors[i].command`. For this store those arguments are session storage keys, `ExternalKey` values, the whole stored session value with its `Data`, and, for a refused `AUTH`, the Redis password. `util.inspect`, `console.error`, `JSON.stringify` and loggers that copy an error's own properties printed them. The store now removes `command` from the error, and from each item of `previousErrors`, before it rethrows the error from `restore`, `save`, `touch`, `delete`, `listBySubject`, `deleteBySubject`, `deleteByExternalKey` and `truncate`, and before it logs a client `error` event. It rethrows the same error object: its class (`ReplyError`, `AbortError`, `Error`), `name`, `message`, `stack` and `previousErrors` stay as they were, so `instanceof ReplyError` and matching `READONLY` or `EXECABORT` in the message still work. Code that read `err.command.name` or `err.command.args` of an error from the store can no longer do that: branch on the message or the class instead.
