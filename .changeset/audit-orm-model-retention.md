`auditOf(Model, trail?)` and `auditOf(row, trail?)` read the audit events of any model (`.of(id)`, `.since(seq)`, `.entries()`), and a model marked `@Auditable()` reads the same through `Model.audit(trail?)` and `row.audit(trail?)`. The mark is refused on a model with its own member named `audit`, which must rename it to take the mark, and a marked model whose table has a column named `audit` must rename the column: it is hydrated onto the row even when the class does not declare it, and hides the method there. `pruneAudit()` deletes the events older than each trail's `retentionDays` on every connection that holds the trail's table, and once, for every source, for a trail with an archive (`archiveConnection`); `@spinajs/audit-orm/scheduler` adds `AuditRetentionTask` (`audit.retention`, daily, leader only). A trail or connection that fails does not stop the others: they are pruned, each failure is logged, then `AuditPruneFailed` gives the deleted count and every failure with its reason in its message, which is what a failed scheduler run keeps. Each trail owns its table: a table-store trail whose table another such trail uses is refused with `AuditConfigError` on write, read and retention, whatever their connections; the other trails keep working. When a model's connection is not the trail's, `auditOf()` and `audit()` read both, each in time order, and merge by time (a connection that cannot be reached fails the read); `since(seq)` above 0 then needs `query.source`. `auditSubjectId(key)` writes a row key as a subject id (composite keys as escaped parts joined with `:`, binary keys as hex) for producers and `row.audit()` alike.
