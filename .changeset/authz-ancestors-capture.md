`AncestorMiddleware` is removed: `AncestorObserver`, a `WriteObserver` on the ORM write capture, keeps `authz_resource_ancestor` right instead, sharing the capture's reads with the column changelog (one key select per write instead of two, and no `stillThere` read after a delete). The rows are the same as before, except: an upsert that updates a row through a unique column now moves that row; a replace that deletes a row through a unique column now forgets it as a delete does; an upsert whose rows the capture cannot find (a unique index over several columns or with an expression or prefix part, a conflict value that is not a string or an integer) rebuilds only the rows whose keys it supplies and warns, so a row it moved without naming its key keeps its old parent until `authz:ancestors-rebuild`. With `db.WriteCapture.MaxRows` set, a delete or `@Parent` update of an access resource above the limit is refused. Every `@AccessResource` model with a composite primary key is refused at domain boot, whether it opted out of the column changelog or not.
