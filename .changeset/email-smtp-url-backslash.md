Security fix: `nodemailer` reads `options.url` and `options.proxy` with the legacy `url.parse()`, which reads a `\` in the user name or password as `/` and takes the user name for the host, where `new URL()` keeps it in the userinfo of an `smtp:`, `smtps:`, `socks:` or registered scheme. Such a url or proxy made `nodemailer` look the user name up and Node print a `DEP0170` warning with the whole URL, password included, to stderr. `resolve()` now refuses a `\` before the last `@` with `InvalidArgument`, before any lookup, connection or warning: write it `%5C`. A `url` in the query of `options.url` (`?url=`), which `nodemailer`'s SMTP transport parses again and dials, is checked the same way. The refusal messages now name `\` and `%5C`. Breaking: such a url or proxy was read by `nodemailer` as a host (and port) taken from its user name or password. It reached that host, never the one the url names, and with an `@` inside the password it sent the credentials there, while the package logged the connection as established to the host the url names. It is refused now: write the `\` as `%5C`.
