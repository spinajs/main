Security fix. With type coercion, the strings `'Infinity'`, `'-Infinity'` and `'1e400'` coerced to non-finite numbers that passed `minimum`, `maximum` and `multipleOf`: Ajv checks the type before it coerces and runs those rules on finite numbers only, and `strictNumbers` does not cover coerced values. `DataValidator` and the manifest validators (`manifestValidatorOf()`, used for `@spinajs/http` request arguments) now fail such a value with a `type` error at the field wherever the schema type lists `number` or `integer`. After a successful validation they, and the `@spinajs/http-socket` contract validator, also refuse any other non-finite number left in the data with a `type` error at its path (`params: { type: 'finite number' }`): a JSON `1e400` under a schema without a `type`, or a value an `if`, an `anyOf`/`oneOf` branch or a `not` coerced before it failed. A value built in code that holds `Infinity` or `NaN` is refused too.

A JSON object with its own `valueOf` or `toString` key, such as `{"valueOf":1}`, made object `const` and `enum`, `uniqueItems` over objects and `uniqueItemProperties` throw a `TypeError`, answered as a 500 by `@spinajs/http` and as `internal` by `@spinajs/http-socket`. These keywords now compare a plain object by its own keys and keep Ajv's rule position, so the value fails or passes the rule like any other and the request answers 400 / `invalid_argument` naming the field. Exceptions to otherwise unchanged verdicts and errors: `uniqueItems` over strings finds a repeated `"__proto__"`; two `{"constructor":{}}` values now compare equal; a value nested more than about 101 000 levels deep throws a `RangeError`. `createAjv()` throws at boot when the installed Ajv no longer has the rule shape the fix relies on; a subclass keeps the fix only when it starts from `super.createAjv()`. `addSafeKeywords`, `jsonEqual`, `findNonFinite`, `nonFiniteErrors` and `dropNonFiniteDuplicates` are exported for other Ajv instances. Raw Ajv errors of these instances carry a `params.nonFinite` marker; `sanitizeError()` drops it.

`prepareManifestSchemas()` kept no property named `__proto__`: `copy[key] =` set the prototype instead, and Ajv then refused the schema. The property is kept; Ajv itself skips that name in `properties`, so a closed object reports a `__proto__` key of the data as `additionalProperties`.
