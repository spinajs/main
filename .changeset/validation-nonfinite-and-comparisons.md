Security fix. With type coercion, the strings `'Infinity'`, `'-Infinity'` and `'1e400'` coerced to non-finite numbers that passed `minimum`, `maximum` and `multipleOf`: Ajv checks the type before it coerces and runs those rules on finite numbers only, and `strictNumbers` does not cover coerced values. `DataValidator` and the manifest validators (`manifestValidatorOf()`, used for `@spinajs/http` request arguments) now fail such a value with a `type` error at the field wherever the schema type lists `number` or `integer`. After a successful validation they, and the `@spinajs/http-socket` contract validator, also refuse any other non-finite number left in the data with a `type` error at its path (`params: { type: 'finite number' }`): a JSON `1e400` under a schema without a `type`, or a value an `if`, an `anyOf`/`oneOf` branch or a `not` coerced before it failed. A value built in code that holds `Infinity` or `NaN` is refused too. At most 100 are listed; the last error's message says when there are more. A path holds at most 64 segments and 1024 characters; a longer one keeps its leading segments, the last of them cut to fit, and ends with `/…`.

A JSON object with its own `valueOf` or `toString` key, such as `{"valueOf":1}`, made object `const` and `enum`, `uniqueItems` over objects and `uniqueItemProperties` throw a `TypeError`, answered as a 500 by `@spinajs/http` and as `internal` by `@spinajs/http-socket`. These keywords now compare a plain object by its own keys and keep Ajv's rule position, so the value fails or passes the rule like any other and the request answers 400 / `invalid_argument` naming the field. Exceptions to otherwise unchanged verdicts and errors: `uniqueItems` over strings finds a repeated `"__proto__"`; two `{"constructor":{}}` values now compare equal; a value nested more than about 101 000 levels deep throws a `RangeError`. `createAjv()` throws at boot when the installed Ajv no longer has the rule shape the fix relies on; a subclass keeps the fix only when it starts from `super.createAjv()`. `addSafeKeywords`, `jsonEqual`, `findNonFinite`, `nonFiniteErrors` and `dropNonFiniteDuplicates` are exported for other Ajv instances. Raw Ajv errors of these instances carry a `params.nonFinite` marker; `sanitizeError()` drops it.

The manifest validators lacked `$data`, ajv-keywords and ajv-merge-patch, so in an explicit `@Schema` class nested in a derived argument the server skipped `prohibited` (a mass-assignment guard), `range`, `regexp`, `uniqueItemProperties`, `transform` and every `$merge` / `$patch` rule without a word, and one `$data` limit anywhere in the closure made the whole argument schema refused: unchecked in `prefer`, a failed boot in `require`. They now have the same keywords as `DataValidator`, with the plugins installed when the first schema naming one is added; they keep their own coercion per wire and still fill no defaults. `@spinajs/http` logs an argument left unchecked in `prefer` as an error instead of a warning.

A manifest schema that names a property `__proto__`, in `properties`, `required`, `dependencies`, `anyRequired`, `oneRequired`, `prohibited` or a `deepRequired` pointer, is refused at preparation with an error naming it: Ajv skips that name, so an open object accepted any `__proto__` value and `required: ['__proto__']` passed without the key. Before, the preparer's `copy[key] =` set the prototype instead and Ajv refused the schema without saying why. `prepareManifestSchemas(manifest, unenforceable?)` leaves such a schema out and records the reason; the http-socket contract validator reports it as the reason a contract cannot be enforced.

Known, pre-existing in Ajv: a recursive union such as `type T = number | T[]` on a coerced wire (query, path, header and cookie values, or `coerceTypes: 'array'` in `DataValidator`) wraps a string into an array of itself until the stack runs out. `DataValidator` and the manifest validators now answer that as a validation error at the root (`keyword: 'maxDepth'`, "the value is nested too deeply to validate"), so the request answers 400 with no stack; only a `RangeError` is caught. Each such request still costs Ajv's recursion (about 15 ms); unrolling recursive `$ref`s on coercing instances is a later task.
