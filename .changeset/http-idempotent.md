`@Idempotent(options?)` routes honour the `Idempotency-Key` header: the first request with a key runs the route, a repeat within `ttl` (default `24h`) replays the stored JSON reply with `Idempotent-Replayed: true`, a repeat while the first runs gets 409 with `Retry-After`, and a repeat with a different body or URL 422 (also while the first runs). A body no parser read (multipart, octet-stream) is compared by its media type and `Content-Length` only. A 5xx, 401, 403, 408, 425 or 429 reply is not stored and the key is released; a client that leaves before the route starts claims nothing; a request whose client disconnects after the route started, or whose route crashed (`crash: true`), keeps its key claimed until the lease ends; a claim that lost a transaction conflict answers 409 `idempotency.claim-conflict` with `Retry-After`. Keys are per route and principal and are kept by `@spinajs/idempotency`, an optional peer loaded only when an `@Idempotent` route registers. With `OrmIdempotencyStore` (the default) the app entry must `import '@spinajs/idempotency'` before the boot, so the ORM reads the `__idempotency` model and migration; a route registered after the Orm resolved without them fails the boot with `RouteRegistrationException`, and so does an invalid `idempotency.*` value or `ttl`. A captured JSON reply now also keeps the headers the route set through `IResponseOptions.Headers`, except `Set-Cookie`, the hop-by-hop headers, `Content-Length` and `Date`. New exports: `createIdempotencyGate`, `createRouteIdempotencyGate`, `IdempotencyGateOptions` and `IdempotencyGateService`. `@spinajs/http` now depends on `@spinajs/principal`.
