# `@spinajs/orm-postgres`

The PostgreSQL driver for the SpinaJS ORM. `PostgresOrmDriver` extends `SqlDriver` from [`@spinajs/orm-sql`](../orm-sql/README.md), sends statements through a [`pg`](https://node-postgres.com/) connection pool, and registers the compilers and quoters that spell SQL the PostgreSQL way.

It does **not** pass driver options through to `pg`: of `db.Connections[].Options` it reads only `Schema`. TLS, `application_name` and session settings come from the `PG*` environment variables or from a driver subclass. It does **not** support scheduled events, `CREATE TABLE ... LIKE` or trigger-based table history.

## Install

```sh
npm install @spinajs/orm @spinajs/orm-postgres
```

Importing the package registers `PostgresOrmDriver` under the driver string `orm-driver-postgres`.

## Features

| Feature | What it does |
| --- | --- |
| [Connection and pooling](01-connection-and-pooling.md) | Configuration keys, the `pg` pool, `search_path`, health probe, retries and pool metrics. |
| [Transactions](02-transactions.md) | One pooled client per transaction, all four isolation levels, savepoints for nesting. |
| [Queries and inserts](03-queries-and-inserts.md) | The SQL a query compiles to: `LIMIT`/`OFFSET`, `ON CONFLICT` upserts, `RETURNING` keys, response types. |
| [Schema DDL and reflection](04-schema-ddl-and-reflection.md) | Column types, identity columns, `ALTER COLUMN`, databases, views, `tableInfo()`, unsupported DDL. |
| [Quoting and parameters](05-quoting-and-parameters.md) | Double-quote identifiers, PostgreSQL literals, `?` to `$n` placeholder rewriting. |
| [Extending the driver](06-extending-the-driver.md) | Subclass `PostgresOrmDriver`, replace it for every connection or one, every DI token it registers. |
| [Customizing dialect compilers](07-customizing-dialect-compilers.md) | Subclass or replace each exported compiler, fill the tokens the driver leaves unsupported. |

## Quick start

```ts sample
import '@spinajs/orm-postgres';
import { FrameworkConfiguration } from '@spinajs/configuration';
import { DI } from '@spinajs/di';
import { Orm } from '@spinajs/orm';
import _ from 'lodash';

export class AppConfiguration extends FrameworkConfiguration {
  public async resolve(): Promise<void> {
    await super.resolve();

    this.Config = _.merge(this.Config, {
      db: {
        DefaultConnection: 'main',
        Connections: [
          {
            Name: 'main',
            Driver: 'orm-driver-postgres',
            Host: '127.0.0.1',
            Port: 5432,
            User: 'app',
            Password: 'secret',
            Database: 'shop',
            Options: { Schema: 'public' },
            Pool: { Min: 2, Max: 20 },
            Migration: { OnStartup: true },
          },
        ],
      },
    });
  }
}

export async function countOpenOrders(): Promise<number> {
  const orm = await DI.resolve(Orm);
  const driver = orm.Connections.get('main')!;

  // COUNT(*) is a BIGINT; node-postgres returns it as a string, so convert it
  const total = await driver.select().from('orders').where('status', 'open').selectCount();
  return Number(total);
}
```

## Dialect at a glance

| Feature | Shared `@spinajs/orm-sql` layer (MySQL spelling) | This driver |
| --- | --- | --- |
| Identifier quoting | `` `backticks` `` | `"double quotes"` |
| Bound parameters | `?` | rewritten to `$1..$n` at execution |
| Generated keys | `LAST_INSERT_ID()` | `RETURNING` rows (`insertReturning: true`) |
| Auto increment | `AUTO_INCREMENT`, `NULL` in `VALUES` assigns the key | `GENERATED BY DEFAULT AS IDENTITY`, `DEFAULT` in `VALUES` assigns the key |
| Upsert | `ON DUPLICATE KEY UPDATE c = VALUES(c)` | `ON CONFLICT (cols) DO UPDATE SET c = EXCLUDED.c` |
| Insert-or-ignore | `INSERT IGNORE` | `ON CONFLICT DO NOTHING` |
| Offset without limit | `LIMIT 18446744073709551615` | bare `OFFSET` |
| `ENUM` / `SET` columns | native types | `TEXT` (plus `CHECK (col IN (...))` for an enum) |
| `DATETIME` / `DOUBLE` / `BLOB` / `JSON` | native names | `TIMESTAMP` / `DOUBLE PRECISION` / `BYTEA` / `JSONB` |
| `UNSIGNED`, column `CHARACTER SET`, inline `COMMENT` | supported | dropped |
| `MODIFY column` | one clause restates the column | `ALTER COLUMN ... TYPE ... USING col::type / SET / DROP` actions |
| `DROP INDEX` | `DROP INDEX i ON t` | `DROP INDEX "i"` |
| `exact()` column | `utf8mb4_bin` | `COLLATE "C"` |
| `CREATE DATABASE IF NOT EXISTS` | supported | throws `NotSupported` |
| `CREATE EVENT`, table history, `CREATE TABLE ... LIKE` | MySQL syntax | not available |
| `DECIMAL` / `NUMERIC` / `BIGINT` read back | driver-dependent | strings |

## Testing

Unit tests need no server; they compile statements against `FakePostgresDriver` (see [Extending the driver](06-extending-the-driver.md#test-a-dialect-change-without-a-server)):

```sh
cd packages/orm-postgres && npm test
```

Integration tests expect the docker fixture from the repository root, on port `15432` by default (override with `ORM_TEST_POSTGRES_PORT`):

```sh
docker compose --profile test up -d postgres
cd packages/orm-postgres && npm run test:integration
```
