# RFC L1b-1: B35.conditions assumes a missing principal attribute compares FALSE

Status: APPROVED and APPLIED (KT2): option 1, plus a pinning case (`eve`, no `contractor`, is capped). L1b dropped its patch and its "C1 pin".

Lane L1b (authz-rbac ranks, subject sets, rules and links), task 6. Fixture file:
`packages/authz-testing/src/behaviour/B35-rules.spec.ts` (frozen kit; F5).

## Problem

Case "subjects.when selects the principals a rule applies to (a principal attribute)" uses the cap
`c1` (`maxRole: 'viewer'` on the project ladder) with
`subjects: { when: { attr: 'principal.attributes.contractor', eq: true } }`. It expects `dan`, who
has no `contractor` attribute, to escape the cap (`file:edit` allowed).

Conditions are three-valued (design §5.9, F3 decision 10, RFC L3-1): for `dan` the condition is
UNKNOWN. A cap or restrict only narrows, so under the rule "UNKNOWN never turns into access, also
not by keeping a narrowing rule from applying" (RFC L3-1, approved), the cap applies to `dan`, and
`file:edit` is denied `role_too_low{viewer, editor}`. The fixture expects the two-valued reading,
the one RFC L3-1 removed from B26.abac. The lane runner made the three-valued rule binding for RBAC
rules (task 6 review C1): restrict and cap apply on UNKNOWN; a threshold keeps the condition in its
deny entry, where the engine binds UNKNOWN by polarity.

Every other B35 case passes.

## Change (proposed)

Make the case independent of the missing-attribute rule, in one of two ways:

1. give `dan` a contractor flag of false in that world:
   `dan: userPrincipal('dan', { attributes: { contractor: false } })` (the `agentDan` principal
   acts for the same `dan`); or
2. write the selector the way an author who wants "only contractors" writes it under three-valued
   logic:
   `when: { all: [{ attr: 'principal.attributes.contractor', null: false }, { attr: 'principal.attributes.contractor', eq: true }] }`.

Either keeps the case's intent (`subjects.when` selects by a principal attribute).

Optionally add a case that pins the rule: a principal without `contractor` is capped
(`role_too_low{viewer, editor}`).

## Affected lanes

- L1b: runs B35.conditions strictly with this case patched as option 1 proposes, through the
  `fixtures` option of `runBehaviour` in `packages/authz-rbac/test/behaviour.l1b.test.ts`. It pins the
  three-valued answer on the unpatched shape in `test/rules/rules.test.ts` ("C1 pin"). Both go
  once the kit carries the change.
- K1/CV1: none, as long as every link carries `org_only`. The canvas rules of design §8.5 read
  `principal.attributes.org_only` (link-members-only) and scope attributes only; org policies come
  from the `org` attribute schema with defaults. A link without `org_only` makes link-members-only's
  deny entry UNKNOWN: the engine denies by polarity but reports `no_access`, since it takes a reason
  only from entries whose `when` is definitely TRUE. That fails closed but tells the link user
  nothing (a note for the core owner).
- Hand-off: nothing enforces `org_only` today (`link.create` takes any `attributes`). The canvas
  link writer (CV1, the S3 calls of design §6.6.4) must always write it, and K1's state loader
  likewise; a canvas `AuthzCommandValidator` for `link.create` could refuse a link without it.
