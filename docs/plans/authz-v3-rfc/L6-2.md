# L6-2: id column of the `job` resource

Problem: `registerAccessResource(JobModel, 'job')` takes the primary key `Id` (integer) as the resource id. The design's route `@Access('job:read', { resource: fromParam('jobId', 'job') })` and fixture B30.status pass the uuid `JobId`. The row is never found, so the `initiator` relation never holds and a user gets 403 on their own job.
Change (one of): (a) an option on `AccessResource`/`registerAccessResource` naming the id column (`authz-orm/src/api.ts`, frozen); (b) C8 loads the row by `JobId` and passes it as the resource instead of `fromParam`.
Affected lanes: L4 (option), C8 (route), L6 (none). Decision needed before C8 starts.

Decision (controller): option (b). authz-orm api.ts stays unchanged. C8 loads the job row by JobId, then checks job:read on the row's resource id (the integer Id).
