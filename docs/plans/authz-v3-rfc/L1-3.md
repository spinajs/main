# RFC L1-3: `AuthzService.covers` and `summary` must read model summaries

Lane L1 (authz-rbac model), task 12. Status: proposed; needs the integrator and the engine owner
(F3). Security-relevant: release-blocking for impersonation (B26).

## Problem

Design §6.2 (line 1489, the ABAC `summarize` paragraph: "`AuthzService.covers` uses it (H18,
B26)") and B26 ("the target's combined GLOBAL permission set") say that `covers` builds each
principal's set from the models' summaries. The engine does not: `Authorizer.covers`
(`packages/authz/src/engine/authorizer.ts`, around lines 429–515) runs one check per permission on
`GLOBAL` (`{ type: '$global' }`) for holder and target and compares the decisions. `summary` uses
model summaries only to pick the candidate names; each entry still comes from a check at `at`.

An RBAC check on `$global` cannot see grants limited to a resource type:

- a grant with a type-only or glob pattern (`{ permission: 'doc:read', on: [{ type: 'doc' }] }`,
  the B16 and §8.2 shapes) gives FALSE on `$global`, because the pattern names `doc`;
- an assignment at a bare type ref (`{ type: 'doc' }`) is not on the `$global` path.

So a target whose `doc:read` comes only from such a grant looks as if it lacks `doc:read`, and a
caller with `user:impersonate` but no `doc:read` passes the strict-subset rule and impersonates it.
A probe through the real host (`.authz-sdd/L1-t12a-engine-probe.txt`) gives
`covers(caller, target) === true`. `GET /user/access` (B25) under-reports the same permissions.

`RbacModel.summarize` is correct since L1 task 12: at `$global` it judges each permission per type
of its `PermissionDef.types` and lists it (conditional where it should be). The engine does not use
it.

## Change

Option A (recommended), asymmetric so that a summary bug can never widen anyone's rights:

- target set = the check at `at` ∪ every routed model's summary entries (never smaller than
  either);
- holder set = the check at `at` only (or its intersection with the summaries), never more than
  the checks prove;
- the engine's own ceiling (`permissions`, `resources`, `expiresAt`) and delegation apply to both
  sides, as the checks already do;
- `summary` (B25) lists summary entries the check denies as `conditional`, for display.

Option B (rejected): RBAC treats a check on `$global` as "some row of some type", OR-ing the
per-type votes. `check(p, 'doc:read', GLOBAL)` would become `allowed: true` with a residual for
every holder of a typed grant, so a route guard without a resource would pass. That widens global
gates.

## Affected lanes

F3 (engine owner, the change), L3 (ABAC `summarize` must be complete for the same reason), L9 and
C3/C4 (consumers of `covers` and `summary`), K1 (canvas conformance runs `covers`).

## Interim

L1 makes no change to check semantics. Until option A lands, B26 impersonation must not ship, or
C3/L9 must refuse to impersonate any target that holds a typed, glob or bare-type RBAC grant.
