# RFC L1-3: `AuthzService.covers` and `summary` must read model summaries

Lane L1 (authz-rbac model), task 12. Status: APPROVED (option A) and APPLIED 2026-10-04 on `authz/E1-covers-summaries` (lane E1).
Security-relevant: release-blocking for impersonation (B26).

## Problem

Design §6.2 (line 1489, the ABAC `summarize` paragraph: "`AuthzService.covers` uses it (H18,
B26)") and B26 ("the target's combined GLOBAL permission set") say that `covers` builds each
principal's set from the models' summaries. The engine does not: `Authorizer.covers`
(`packages/authz/src/engine/authorizer.ts`, around lines 429–515) runs one check per permission on
`GLOBAL` (`{ type: '$global' }`) for holder and target and compares the decisions. `summary` uses
model summaries only to pick the candidate names; each entry still comes from a check at `at`.

An RBAC check on `$global` is a concrete request on the global node: only GLOBAL assignments count
there, and only grants that reach `$global`. It does not show permissions the principal holds
below the global node:

- an assignment at a scope (`org:o1`), or at a bare type ref (`{ type: 'doc' }`);
- a grant limited by a pattern: type-only (`{ permission: 'doc:read', on: [{ type: 'doc' }] }`,
  the B16 and §8.2 shapes), glob, or exact id (`file:f1`).

So a target whose `doc:read` comes only from such a grant or assignment looks as if it lacks
`doc:read`, and a caller with `user:impersonate` but no `doc:read` passes the strict-subset rule
and impersonates it. A probe through the real host (`.authz-sdd/L1-t12a-engine-probe.txt`; the
skipped lane part `B26.rbac-probe` in `packages/authz-rbac/test/behaviour.model.test.ts`) gives
`covers(caller, target) === true`. `GET /user/access` (B25) under-reports the same permissions.

The callers that check on `$global` are explicit global gates (`can(p, perm, GLOBAL)`, the
AdminGuard's last-holder rule), `covers` and `summary`. A check without a resource runs on
`{ type: def.resource }` (design §10.1; `authorizer.ts` `resolveResource`), not on `$global`, so
route guards are not affected.

`RbacModel.summarize` is complete since L1 task 12: at `$global` it judges each permission per type
of its `PermissionDef.types` and lists it (conditional where it should be). The engine does not use
it.

## Change

Option A (recommended), asymmetric so that a summary bug can never widen anyone's rights:

- target set = the check at `at` ∪ every routed model's summary entries (never smaller than
  either);
- holder set = the check at `at` only (or its intersection with the summaries), never more than
  the checks prove;
- the engine's own ceiling (`permissions`, `resources`, `expiresAt`) and delegation apply to both
  sides, as the checks already do;
- `summary` (B25) lists summary entries the check denies as `conditional`, for display.

Option B (rejected): RBAC treats a check on `$global` as "some row of some type", OR-ing the
per-type votes and scoped assignments into a conditional residual. Every explicit global gate
would then answer `allowed: true` (with a residual and no subject) for a principal who holds the
permission only on one org or one file, so a "may do X everywhere" gate would pass for a
"may do X somewhere" holder.

## Affected lanes

F3 (engine owner, the change), L3 (ABAC `summarize` must be complete for the same reason), L9 and
C3/C4 (consumers of `covers` and `summary`), K1 (canvas conformance runs `covers`).

## Interim

L1 does not widen checks on `$global` (option B). Until option A lands, B26 impersonation must not ship, or
C3/L9 must refuse to impersonate any target that holds a scoped, bare-type or pattern-limited RBAC
grant.

## As built

Lane E1 built option A with these refinements (RFC E1-1 for the deny rule):

- **Per type at `$global`.** Holder and target are compared on the `$global` node and on
  `{ type: T }` for every type of the permission (review C1). A summary entry is covered only by
  a holder unconditional on every compared ref, with the entry's fields.
- **A target's denies never shrink its set.** An earlier step dropped a summary entry when the
  target's own checks denied it on every row. Review C4 showed that a deny may rest on session
  facts (authn, actor) that change under impersonation, so the step is gone (RFC E1-1).
- **Fail closed.** `covers` is false when a model routed for the target gives no summary (no
  `summarize`, a failure, a timeout or a malformed one).
- **`summary` (B25).** A name a summary lists but the check at `at` denies is listed
  `conditional: true`, with the union of the entries' fields less `neverRead`.
- **ABAC `summarize` gaps closed (L3 hand-off).** At `$global` it judges per type of the
  permission. It lists as conditional a scoped permit, a permit whose condition is false now but
  reads the session, env, time or a function, a permit that fails only on `actorTypes`, and a
  permit whose `principalTypes` match only through a companion the target carries now. Fields are
  the union of every found permit's fields. Deny policies add no entry and remove none.
- **RBAC `summarize`.** Per type at `$global`. Fields are the union of every grant that permits
  some row (`summaryFieldGlobs`, `RBAC_SUMMARY_STEPS`); votes keep `voteFieldGlobs`.

### Hand-offs

- **L7 and every future model** that can grant below `$global` must implement `summarize`;
  without it `covers` is false for every target it routes.
- **C3 (impersonation guard).** `covers` judges at one instant with the target object given.
  Holder allows that expire, or depend on env, scope or principal attributes, are point-in-time;
  consider ending the impersonation at the earliest `validUntil`. `actor.*` is judged with the
  target as actor. Judge the target with the companions (and actor) its impersonated session will
  carry, or build that session without companions: `covers` does not see a `principalTypes`
  permit (ABAC) or a companion's assignments (RBAC, `defaultSubjects`) that only a future
  companion would bring.
- **RBAC rules lane.** Type-level deny entries stay under the rule's scope.
