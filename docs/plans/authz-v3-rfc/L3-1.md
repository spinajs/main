# RFC L3-1: B26.abac case 1 assumes a missing principal attribute compares FALSE

Status: APPROVED (option 1, plus the optional pinning case) and APPLIED 2026-10-03 in 05cf5a9a6 (K2). L3 dropped its patched copy of the case and its own pinning test; the kit case now pins the three-valued rule.

Lane L3 (authz-abac and core conditions), task 8. Fixture file:
`packages/authz-testing/src/behaviour/B26-covers-guard.spec.ts` (frozen kit; F5).

## Problem

Case "an ABAC deny policy takes a permission out of the holder's set" uses the deny policy
`ops-no-delete` (`doc:delete` when `principal.attributes.dept eq 'ops'`) and expects
`covers(ops, t) === false`. The target `t` is `userPrincipal('t')`, which has no `dept`.

Conditions are three-valued (design §5.9, F3 decision 10, the kit's own oracle rule "unresolved refs
are UNKNOWN; at the isAllowed level this denies exactly where bindRefs, fail closed by polarity,
does"). For `t` the condition is UNKNOWN, so the deny policy is UNKNOWN, and `t` is denied
`doc:delete` as well (fail closed: UNKNOWN never turns into access, also not by keeping a deny
from applying). Then `ops` holds every permission `t` holds plus more, so `covers(ops, t)` is true.
The fixture expects `t` to keep `doc:delete`, which needs a missing attribute to compare FALSE
(two-valued), the reverse of what the engine does with a missing `principal.*` ref in a residual.

The other three B26.abac cases and every other L3 part pass.

## Change (proposed)

Make the case independent of the missing-attribute rule, in one of two ways:

1. give the target a department other than `ops`:
   `t: userPrincipal('t', { attributes: { dept: 'dev' } })`; or
2. write the policy the way an author who wants "only ops" writes it under three-valued logic:
   `when: { all: [{ attr: 'principal.attributes.dept', null: false }, { attr: 'principal.attributes.dept', eq: 'ops' }] }`.

Either keeps the case's intent (an ABAC deny on the holder counts in covers).

Optionally add a case that pins the rule: with `t` lacking `dept`, `covers(root2, t)` is true and
`t`'s `doc:delete` is denied (the deny is UNKNOWN for `t`).

## Affected lanes

- L3: runs B26.abac strictly, with this case patched as option 1 proposes in its own copy of the
  catalogue (`packages/authz-abac/test/behaviour.test.ts`), and pins the three-valued answer on
  the unpatched case in a test of its own. Both go once the kit carries the change.
- C3 (B26.abac is also C3's): the same expectation holds there.
- K1/canvas: none.
