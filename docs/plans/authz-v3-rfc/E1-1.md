# RFC E1-1: B26.abac expects a target's deny policy to shrink its set in covers

Status: proposed.

Lane E1 (engine: covers reads model summaries, RFC L1-3), task 1. Fixture file:
`packages/authz-testing/src/behaviour/B26-covers-guard.spec.ts` (frozen kit; F5).

## Problem

Case "a deny policy on an attribute the target lacks is UNKNOWN for it, which denies (RFC L3-1)"
in `B26.abac` expects `covers('ops', 't') === true`. The deny policy `ops-no-delete` reads
`principal.attributes.dept`, which `t` lacks, so it is UNKNOWN for `t` and `t`'s check of
`doc:delete` denies. `ops` lacks `doc:delete` too.

Under option A of RFC L1-3, `t`'s set is its checks and its model summaries. The fake RBAC summary
lists `doc:delete` for `t` (role `deleter`), and `ops` does not hold it, so `covers` is false.

An earlier draft of E1 let a deny that holds for the target on every row clear the summary entry.
Review C4 showed a hole in that: covers judges the target's deny with no actor and with the
session facts the target object carries, while the impersonated session may carry other facts.
A deny on `principal.authn.assurance ne 'aal2'` holds for a target with no `authn`, and no longer
holds once the impersonator logs in with MFA. A deny on `actor.attributes.*` holds with the target
as actor, and no longer holds when the impersonator is the actor. In both, the impersonator gains
`doc:delete`. The engine cannot tell from a vote which facts the deny read without a contract
change, so it now keeps the entry whatever the target's denies say.

## Change

In the case above, expect `covers('ops', 't', false)`. Keep the check step and
`covers('root2', 't', true)`. Rename the case, for example: "a deny policy on an attribute the
target lacks denies it, but does not shrink its set in covers (RFC L3-1, RFC E1-1)", and say in
the note that a target's deny policy may rest on session facts (authn, actor) that change under
impersonation, so covers does not let it shrink the target's set.

## Affected lanes

- F5 (kit owner): the change above.
- L3: runs B26.abac from a patched copy of the catalogue in which only this case's
  `covers('ops', 't')` expects false (`packages/authz-abac/test/behaviour.test.ts`). The copy goes
  once the kit carries the change. `test/model/summarize.test.ts` already expects a target's deny
  policy to leave its permit entry in place.
- C3 (B26.abac is also C3's): the same expectation holds there. Impersonation can only refuse
  more targets than before; none it refused before is now let through.
