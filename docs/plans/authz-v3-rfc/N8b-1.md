# N8b-1: a `CredentialAdminGuard` hook in the authn contracts (A25, SR-10)

Status: proposed (N8b, 2026-10-05). Needs a decision by the controller.
Owners of the change: F6's frozen file `packages/authn/src/contracts/hooks.ts`
(plus the contracts barrel and the api snapshot), C3 (users implements it),
N8b (authn-http routes use it). N8b task 5 (credential admin routes, A25,
`SR-10 …` tests) stops until this is decided.

## Problem

Design §22.11 puts the credential admin routes
`/authn/admin/users/:uuid/{password-reset,mfa-reset,sessions,tokens}` in
authn-http behind `@Access('users:credentials')` and the target guard (A25,
SR-10). authn-http may not depend on any `authz*` package nor on `users`
(plan §1 rule 10), so it cannot use `@Access` or call users'
`AuthzTargetGuard.checkIdentity` (C3). users depends on `@spinajs/authn`
and `@spinajs/authn-local` only, not on authn-http, so a hook class declared
in authn-http cannot be implemented by users either. C3's report and the
controller's hand-off ask for an authn-level contract. N8a's report said "a
hook C3 registers"; no such contract exists yet.

The kit already models the split: `ActorsPort.admin({ credentialsRight })`
gives an admin with or without `users:credentials`, and `GuardPort`
(`targetGuard`) denies a target with `forbidden`, `protected_role` or
`escalation` (`packages/authn-testing/src/harness/ports.ts`). No kit change
is needed.

## Change

Add to `packages/authn/src/contracts/hooks.ts` (exported by the contracts
barrel, like `RoleSource`):

```ts
/** The credential admin routes of authn-http (A25). */
export type CredentialAdminAction = 'password-reset' | 'mfa-reset' | 'sessions' | 'tokens';

/**
 * users: AuthzCredentialAdminGuard (D26 pattern). None registered ⇒ the credential admin routes are off (404).
 * forbidden: the actor lacks users:credentials at GLOBAL, or is impersonating, or did not sign in interactively;
 * protected_role: the target holds a protected role; escalation: the actor does not cover the target's rights (B26
 * strict subset, AuthzService.covers); not_found: no such target. The routes call it before any effect (A25: a refused
 * call changes nothing).
 */
export abstract class CredentialAdminGuard {
  abstract allowed(actor: Principal, target: IdentityRef, action: CredentialAdminAction): Promise<{ ok: true } | { ok: false; code: 'forbidden' | 'protected_role' | 'escalation' | 'not_found' }>;
}
```

- **C3 (users)**: `AuthzCredentialAdminGuard` in `packages/users/src/authn/`,
  registered with the other hooks: refuse an impersonating actor and a
  non-interactive sign-in (`forbidden`), check `users:credentials` at GLOBAL
  through `AuthzService` (`forbidden`), then `AuthzTargetGuard.checkIdentity`
  (`protected_role`, `escalation`; its `ResourceNotFound` becomes
  `not_found`). The permission name may come from config
  (`authz.credentials.permission`, default `users:credentials`), as
  impersonation's does. `action` lets an app narrow per action; users' default
  ignores it.
- **N8b (authn-http)**: `AuthnCredentialAdminController` gates the group on a
  registered `CredentialAdminGuard` (404 otherwise), requires an
  `Authenticated` full session principal, fresh auth in the handler (lane
  decision: policies run concurrently), then `allowed(...)` before any
  service call; refusals answer 403 with the code (`not_found` → 404).
  Effects: password reset = `PasswordService.expire` (+ reset mail through
  `requestReset`-like issue, no secret in the answer) and `revokeAll` /
  `revokeAllFor`; MFA reset = `TotpService.adminReset`; sessions =
  `SessionIssuer.revokeAll(target, { includeImpersonations: true })`; tokens =
  `TokenService.revokeAllFor`. Kit A25/http over a fake guard driven by the
  `targetGuard` and `actors` ports; `SR-10 …` route tests.
- **F6 / integrator**: api snapshot update for `@spinajs/authn` contracts.

## Alternatives

- B: declare the abstract class outside the frozen folder
  (`packages/authn/src/hooks/credential-admin.ts`, exported from the
  `@spinajs/authn` root). No RFC needed, but authn-http must then import the
  authn root, which registers services at load, so it could only reach it
  lazily, and the hook would live apart from `RoleSource` and
  `ImpersonationGuard`.
- C: reuse `ImpersonationGuard`. Wrong permission (`user:impersonate`) and
  meaning; rejected.
- D: authn-http checks the permission itself. Needs authz; violates rule 10.
