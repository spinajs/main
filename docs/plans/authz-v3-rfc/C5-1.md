# RFC C5-1: B08.token has no cases

Status: APPROVED (option C) and APPLIED 2026-10-05 (KT1): two B08.token cases in a `tokenWorld` variant plus the `agentFor` step; C5 adds `B08.token` to `packages/authz-rbac/test/token/behaviour.test.ts`. Lane C5 (token principals on authz). Kit
file: `packages/authz-testing/src/behaviour/B08-intersect.spec.ts` (part
`token`, lanes `C5`, `cases: []`, note "C5 proposes the cases by RFC").
Owner of the change: the kit owner (C5 never edits `authz-testing`).

## Problem

B08 is `intersect` delegation: the answer is at most the delegate's, and
the delegate must allow too. The plan lists B08 in C5's acceptance, and
the kit leaves C5 a `token` part with no cases, so a run of the bare id
`B08` reaches an empty part.

authn-token never issues an `intersect` token. The frozen contract
(`packages/authn/src/contracts/token.ts`, `TokenValidation`) gives a
personal or service token no delegation (the owner is the identity; its
roles are `ceiling.roles`) and an agent token `mode: 'inherit'` (A15,
B37). Other strategies may still return `intersect`: `StrategyOutcome`
allows it, and an app may build its own agent that acts for a principal
which authenticated with a token.

That last case is the one real authz behaviour behind "B08 with tokens":
when the delegate of an `intersect` chain is a token principal, the
engine's nested check runs as that delegate, and RBAC must apply
`authz.token.*` there (excluded roles, the role policy, `ceiling.roles`).
No kit part covers it today.

## Change (proposed)

Option C (preferred): one or two B08.token cases in `tokenWorld` (B24),
with `config.token.excludedRoles: ['route.*']`:

- an app agent (`delegation: 'intersect'`, its own `report:export` grant)
  acting for a token principal of alice (`token('t', { owner: 'alice',
  roles: ['editor', 'route.export'] })`) is denied `report:export` with
  reason `delegate`: the nested check of the token principal drops the
  excluded role;
- the same agent is allowed `file:write`, which both it and the token
  principal hold.

The kit needs a step that builds a principal acting for a kept principal
(an `onBehalfOf: { kept: 't' }` form, or a `do` helper
`agentFor(key, kept, init)`).

Option B (fallback, if the kit cannot express C): drop the `token` part
from B08 and the plan's C5 acceptance line, and say in the B08 note that
authn-token issues no `intersect` tokens (B37 covers agent tokens).

## Affected lanes

- Kit owner: the B08 spec and, for option C, the step helper.
- C5: adds `B08.token` to `packages/authz-rbac/test/token/behaviour.test.ts`
  once the cases exist. The RBAC side needs no change: the token rules
  apply to any principal with `authn.method: 'token'`, which is what the
  nested check runs as.
- Plan: C5 acceptance line (option B only).
