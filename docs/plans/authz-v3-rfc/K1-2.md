# RFC K1-2: DbScopeAttributeStore refuses to read a node whose id is longer than its columns

Status: PROPOSED.

Lane K1 (canvas C6 conformance), task 7. Owner of the change: authz-orm
(`DbScopeAttributeStore`); the engine owner only for the option below. No frozen contract changes.

## Problem

On SQLite with the §8.5 stores, the five branch cases of canvas `cases.json` answer
`model_error`; in memory they conform:

| Case | Expected | Got on SQLite |
| --- | --- | --- |
| editor edits unprotected branches | `{ allowed: true, role: 'editor' }` | `{ allowed: false, reason: { code: 'model_error' } }` |
| main needs maintainer to push | `branch_protected { pattern: 'main', needed: 'maintainer' }` | same `model_error` |
| release push is open to editors | `{ allowed: true, role: 'editor' }` | same |
| release merge needs maintainer | `branch_protected { pattern: 'release/*', needed: 'maintainer' }` | same |
| overlapping branch rules report the first pattern by code point | `branch_protected { pattern: '*-lts', needed: 'maintainer' }` | same |

## Engine path

1. A C6 branch has no id of its own (`{ kind: 'branch', project, file, branch }`); its ref is
   `branch:<project>:<file>:<name>` (`packages/authz-testing/test/canvas-c6/scope.ts`,
   `branchRef`): 74 characters plus the percent-encoded name when the branch has a file (78 for
   `main`), 38 plus the name without a file. Any id that carries a user-chosen branch name can
   pass 64 characters.
2. The §8.5 branch rows are threshold rules with `resource: { attr: 'resource.name', wildcard }`;
   the engine reads node attributes for `resource.*` refs (ScopeResolver contract: "Attributes of
   one node for 'scope.<type>.*' and 'resource.*' refs (canvas: org policies, branch name)").
3. `Authorizer.loadAttributes` (`packages/authz/src/engine/authorizer.ts:1717-1738`, `store.get` at
   `:1729`) layers schema
   defaults, the resolver's attributes and `store.get(ref)` for the branch node.
4. `DbScopeAttributeStore.get` (`packages/authz-orm/src/scope-attributes/db-store.ts:53`) →
   `rows` (`:64`) → `select` (`:107`) → `keyOf` (`:148-152`) throws
   `AuthzConfigError: DbScopeAttributeStore: {"type":"branch",…} does not fit
   authz_scope_attribute.scope_type/scope_id (64 characters each)`.
5. The RBAC vote becomes indeterminate (B04); deny-overrides answers `model_error`.

A probe that returned `{}` for such ids gave 64/64 on SQLite, so this is the only cause.

## Who is wrong: SpinaJS

A `ResourceRef` id has no length limit in the contract; the design gives the authz tables
`scope_id varchar(64)`, which limits only the nodes that hold rows, so it matters only for a
write. `DbLinkStore.byToken` already answers "no row" without a query for an over-length key
(`LINK_TOKEN_MAX_LENGTH`, `packages/authz-rbac/src/stores/db-link-store.ts:31,268-270`). The other DB stores read long ids: `scopeToColumns`
(`packages/authz-rbac/src/stores/columns.ts`) has no length check, and `DbRuleStore.forPath` reads
the same branch ref in its path on these very checks. A node whose key cannot fit the table cannot
have rows, so its stored attributes are `{}`. Refusing the read turns every check on such a node
into `model_error`, for any app with composite or long scope ids. Design §16.3 row 10 needs the
branch rows over branch refs with the name from the resolver, and B40 asks for 64/64 on SQLite.

A bounded branch id on the canvas side (a hash, with the name served by the resolver) would avoid
the throw, but it would need a lookup table from hash to branch, only to work around a read that
cannot find rows anyway; it moves a store limit into every app's ids, so K1 rejects it.

## Proposed change

In `DbScopeAttributeStore`: `get` and `rows` (the `WritableScopeAttributeStore` port method the
admin handler calls before `write`, `packages/authz/src/admin/scope-attributes/handler.ts:100`)
return `{}` without a query when the ref's type or id does not fit the columns; `write` and
`forget` keep the `AuthzConfigError`, so `scope.setAttributes` on such a node reads `{}` and then
fails in `write`. Add a test with a 65+ character id.

Option for the engine owner: skip the store for scope types without a registered
`ScopeAttributeSchema` (canvas `branch` has none), which also saves one query per branch check;
it changes when the store is consulted, so it needs that owner's view. `scope.setAttributes`
already refuses a type with no registered schema (`handler.ts:94`, `invalid_attributes`), so for
such types the skip loses nothing written through AuthzAdmin.

## Affected lanes

- authz-orm scope attribute store owner: the fix and its test.
- K1: remove the five `sqlite` pins in `packages/authz-testing/test/canvas-c6/mismatches.ts`
  (the tests then fail until unpinned, by design).
- CV1: the same defect hits canvas on any database (`keyOf` throws before any SQL) whenever a
  branch id passes 64 characters.
