# E2-1: a type-only scope in `under` matches any ancestor of that type

Status: proposal (E2 item 2, closing point 2 of RFC L1-2). Owners of the change: the kit owner
(K4 / F5, `@spinajs/authz-testing`) and F1 (the `under` doc comment in
`packages/authz/src/contracts/filter.ts`, frozen). E2 changes no engine code for it.

## Problem

`{ op: 'under', scopes: [{ type: 'project' }] }`, a scope with no id, has two readings in the tree:

| Reader | Reading |
|---|---|
| engine, `packages/authz/src/engine/evaluate.ts` `under` | some ancestor of the row (the row included) has type `project` |
| SQL, `packages/authz-orm/src/compile/compiler.ts` `scopeRef` | the same: TRUE for the row's own type and `$global`, else a non-NULL `@ScopeColumn` of that type |
| ABAC, `packages/authz-abac/src/model/policies.ts` `scopeFilter` | the same ("a scope without id is any node of its type, as `under` reads it") |
| kit oracle, `packages/authz-testing/src/filter-eval.ts` `under` | `sameRef`: only an ancestor that is itself the type-only ref `{ type: 'project' }` |

Real ancestor lists hold concrete refs (`{ type: 'project', id: 'p1' }`), so under the kit's reading
a type-only scope matches almost nothing: only type-level refs, whose ancestors are `[{ type }, $global]`.
L1's fast-check property found the split: `under [{ type: 'project' }]` selected no file rows in the
kit, while the engine and the check path allowed them. L1 now never emits a type-only scope in a
row filter, so no fixture depends on either reading today.

The contract comment, "the row has one of these as an ancestor (or is one)", does not say what a
scope without id means.

## Decision proposed

Keep the engine's reading: it is F3 decision 10 ("`under` with a type-level scope matches any node
of that type"), the SQL and ABAC already follow it, and the engine is the reference semantics for
SQL. Changing the engine instead would need SQL and ABAC changes and would make a type-only scope
useless in row filters.

## Change

1. Kit (`filter-eval.ts` `under`): a scope without id matches an ancestor of the same type,
   whatever its id; a scope with id keeps `sameRef`. Add the rule to the `evaluateFilter` comment
   next to "`under []` = FALSE", and a unit case (a file row under project p1 is `under
   [{ type: 'project' }]`; a row with no project ancestor is not).
2. Contract doc comment (frozen, D3): the `under` member of `ResourceFilter` in
   `packages/authz/src/contracts/filter.ts` reads
   `// the row has one of these as an ancestor (or is one); a scope without id matches any node of its type`.
   The API snapshot (`packages/authz/etc/*.api.md`) changes with it. The design §6 listing
   (`2026-10-01-authz-v3-design.md`, the `under` line of `ResourceFilter`) gets the same words.

## Affected lanes

- K4/F5: the kit change and its unit case.
- F1/integrator: the doc comment and the snapshot.
- L1: may drop its "never a type-only scope in a row filter" guard after the change, but need not.
- L3, L4: none; they already follow the engine.
