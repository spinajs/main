# L9-1: type `authz:scope.manage` in the B39.store fixture

Status: proposed (L9, 2026-10-03). APPROVED and APPLIED 2026-10-04 (K3): the B39.store world declares
`authz:scope.manage` with `types: ['org']`, and L9's admin harness no longer patches the permission, so the kit
cases run unchanged. Owner of the change: the `@spinajs/authz-testing` kit.

## Problem

`packages/authz-testing/src/behaviour/B39-scope-attributes-store.spec.ts` declares its permissions as
`['file:read', 'authz:scope.manage']`. A permission declared as a bare name applies only to the type
in its name, so `authz:scope.manage` applies to type `authz`. The part's cases run
`scope.setAttributes` and `scope.replaceAttributes` on `org:o1`, and `AuthzAdmin` checks the
command's permission at its scope (lane design §3.2, design §6.6.2 table). The engine refuses a check
on a type the permission does not declare before the SYSTEM short-circuit, so every write case fails
with `AuthzConfigError` ("permission "authz:scope.manage" is checked on type "org", which is not in its
types (authz) or $global"). B43.attributes declares the same permission with types and passes.

## Change

In the B39.store world, declare the permission with the scope type it is checked on:

```ts
permissions: ['file:read', { name: 'authz:scope.manage', types: ['org'] }],
```

No other fixture, engine or contract changes.

## Affected lanes

- L9: `packages/authz/test/admin/scope-attributes-behaviour.test.ts` gives `authz:scope.manage` the
  world's scope node types when a world declares it untyped. That workaround stays until this change
  lands, then goes.
- Any other lane that runs B39.store (none today; the part lists `lanes: ['L9']`).
