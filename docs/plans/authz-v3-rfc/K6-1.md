# RFC K6-1: per-provider linking switches in the strategy contract

Status: PROPOSED (non-blocking; K6 ships the behaviour without a frozen-contract change).

Step K6, item 4 (M1 fact check). Frozen contract: `packages/authn/src/contracts/strategy.ts`.

## Problem

F6 and N10 say JIT provisioning and linking by verified email each need the global `authn.linking` switch and the
provider's own switch. Only authn-oidc enforced its half, inside the strategy. `JwtBearerStrategy` answers external
subjects too, so turning `authn.linking.jit` on for OIDC also provisioned accounts for any subject of a configured JWT
issuer.

## What K6 did (no frozen file touched)

- `ExternalLinkingStrategy` / `linkingSwitchesOf` in `packages/authn/src/link/switches.ts` (not frozen): a strategy
  may answer `linkingFor(external): { jit, byVerifiedEmail }`. `DefaultAuthnService` provisions or links by email
  only when the global switch and this switch are both on. A strategy without the method, or whose method throws or
  answers anything but booleans, gets neither.
- `OidcStrategy.linkingFor` answers its provider's `linking`; `JwtBearerStrategy.linkingFor` answers the issuer's new
  `linking.jit` (default off) and never `byVerifiedEmail`. The kit's `FakeStrategy` takes a `linking` option
  (`FakeStrategy.external` defaults to both on) and `FakeAuthnService` applies the same rule.

## Change (proposed)

Add the method to the contract as an optional member, so a third-party external strategy (LDAP, SAML) sees it there:

```ts
/** External strategies: this provider's own JIT and verified-email switches; authn.linking applies only with them. */
linkingFor?(external: ExternalSubject): { readonly jit: boolean; readonly byVerifiedEmail: boolean };
```

## Affected

N11 and N12 (they implement it), M1 (migration guide: the JWT issuer `linking.jit` key).
