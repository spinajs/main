# E2-2: native ops whose args bind the principal survive the intersect strip

Status: APPROVED 2026-10-05 by the controller and APPLIED by E3: changes 1 to 4 and the engine and
authz-rbac tests of change 5 (see "As applied" at the end).

Original status: proposal (E2 final review, finding I1). Owners of the change: F1 (`NativeFilter` in
`packages/authz/src/contracts/model.ts`, frozen), the engine (E2 or a later engine step), L1b
(`authz-rbac` filters). E2 ships the fail-closed behaviour below until the controller decides.

## Problem

Under intersect delegation the engine strips every `relation` and `native:*` leaf of the
delegate's residual (`stripPrincipalOps`, FALSE under an even number of `not`s), because SQL and
the subject evaluator read those ops as `Decision.principal`, not the delegate. Since E2 commit 1
the row check does the same, so filter and check agree (B06).

`native:rbac.assignment` and `native:rbac.threshold` (L1b, `authz-rbac/src/model/rules/native.ts`)
do not read the principal from the context: their args carry it (`principal`, `subjects`,
`companions`), `RbacAssignmentFilter.matches` reads the args, and the ORM compiler ignores its
`principal` parameter (`authz-rbac/src/orm/rbac-orm-compiler.ts:70`). Stripping them is not needed
for correctness, but the engine cannot tell them from ops that do read the principal.

Effect, measured by the E2 final review (`.authz-sdd/E2-final-review-probe.txt`): a delegate with a
GLOBAL viewer role and a DB rule store (no rules in it), or a viewer role at p1, gets a native
type-level vote. An intersect agent acting for that delegate now gets `check` denied (reason
`delegate`) on every row, where before E2 the row check allowed and only the list was empty. With
config rules only and a GLOBAL role the vote is TRUE and nothing changes.

## Change

1. Contract (`NativeFilter`, frozen): an optional declaration, e.g.
   `readonly principalInArgs?: boolean; // args name every principal the op reads; the op never reads Decision.principal`.
   The doc comment and `etc/authz.api.md` change with it.
2. Engine: `stripPrincipalOps` keeps a `native:*` leaf whose registered `NativeFilter` declares
   `principalInArgs`, in the filter and in the row check alike (the Authorizer passes its native
   index to the strip). `relation` leaves stay stripped (a `relation` node names no principal).
3. authz-rbac: `RbacAssignmentFilter` and the threshold filter declare `principalInArgs: true`;
   their ORM compiler already ignores the principal.
4. authz-orm: an `OrmNativeCompiler` of such an op must not read its `principal` parameter; say so
   in the `@spinajs/authz-orm/native` README section.
5. Tests: the B06 intersect properties (engine, authz-orm) gain a principal-in-args native leaf
   that must be kept and agree; authz-rbac pins that an intersect agent for a delegate with a
   native RBAC list vote gets the rows the delegate's assignments reach.

## Until then

E2 keeps fail-closed: such intersect agents see no rows in lists (as before E2) and are denied on
row checks (new in E2). Release notes should say so.

## Affected lanes

- F1: the declaration and its doc comment.
- Engine owner: the strip change.
- L1b: the two filters declare it.
- L4: the README note for native compilers.

## As applied (E3)

- Contract: `principalInArgs` is declared in an interface merged into `NativeFilter`, not as a class
  field. It emits no JS under any `useDefineForClassFields`, and a subclass may declare it with a
  field initialiser or a getter (a class field would make TS refuse the getter, TS2611). Its doc
  comment also requires a flagged filter to key every `ctx.cache` memo by what its args name: a
  kept leaf runs with the agent's evaluation context and cache, so a memo keyed only by the
  engine's per-principal cache namespace would let the delegate's leaf and the agent's own leaf
  read each other's answers.
- Engine: the Authorizer reads `filter.principalInArgs === true` once per filter when it is built
  (duck-typed; a throwing getter counts as false) and passes those ops to `stripPrincipalOps(f,
  keep?)` at both strip sites, so filter and check still agree (B06).
- authz-rbac: `RbacAssignmentFilter` and `RbacThresholdFilter` declare it. `RbacOrmCompiler`
  ignores its `principal` parameter; there is no SQL compiler for args v2 or
  `native:rbac.threshold` yet (L4b).
- Not done here: the authz-orm B06 property's native leaf is the kit's `native:fake.tuple`
  (`@spinajs/authz-testing`), so it gains no flagged leaf in E3. authz-rbac's SQL case runs
  `RbacOrmCompiler` on a driver query, not through the authz-orm middleware, which refuses that
  compiler's lazy `EXISTS` for every principal until L4b moves it to `@spinajs/authz-orm/native`.
