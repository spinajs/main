# C3-2: B25.authn cannot run with users' real role source and impersonation guard

Status: proposed (C3, 2026-10-05). Owner of the change: the `@spinajs/authz-testing` kit (F5/KT lanes). Affects C3
(acceptance), N8c (cutover), T2.

## Problem

Plan C3's acceptance lists B25 (part `authn`): each flow answer (login, MFA completion, role switch, impersonation)
carries `Access`, equal to `GET /user/access` for the principal the session then yields. The part runs on
`kitWorld(false)`, whose RBAC is the kit's `fake-rbac` model, with facets `engine`, `http`, `authn` (no `rbac`).

users implements the hooks the role switch and the impersonation flow call (design D26): `RbacRoleSource` and
`AuthzImpersonationGuard` (through `AuthzTargetGuard`). Both read authz-rbac: `RbacModel.inputAt` for the roles a
principal holds at any scope, and the protected-role scan. In a world without the RBAC model they throw
`AuthzConfigError` (fail closed, by design), so "the role switch response carries Access" and "the impersonation
response carries Access" cannot pass with users' real hooks. The login and MFA cases would.

B24.roleSwitch has the same shape question: its world must hold real RBAC for users' role source.

## Change

Either:

1. give B25's `authn` part (and B24's `roleSwitch` part) a world with the `rbac` facet and real role definitions
   (the authz-rbac `RbacModel` over the world's roles, as `hostHarness` already does for `rbac` parts), or
2. state in the part's note that its role-switch and impersonation cases run with the kit's fake hooks
   (`FakeRoleSource`, `FakeImpersonationGuard`), and add a separate `rbac` part that users runs with its real hooks.

Option 1 tests what ships; option 2 keeps the part independent of authz-rbac.

## Not blocked by this RFC alone

Running these parts in a users test process also waits on N8c (users' 2.x session classes clash by name with
authn-session's; the authn-http barrel still loads the 2.x stack) and on a shareable http + authn harness (today only
authn-http and authz-http test code). Details: `.authz-sdd/C3-acceptance-report.md`, part B.
