# RFC K1b-1: an agent's canvas list is empty while its row checks allow (ABAC agents-disabled on lists)

Status: APPROVED (option A) and APPLIED by lane A4 (branch `authz/A4-abac-scope-sql`). See "Applied".

Lane K1b (canvas C6 list conformance through authz-orm SQL), plan K1 task 9. Owner of the change:
authz-abac (L3), with authz-orm (L4) for the SQL side; the design owner for §8.5 and B19. No frozen
contract change is needed for options A or C.

## Problem

Every list of an agent principal is FALSE under the §8.5 config, also where the agent's row checks
allow. The in-memory `filter` and the SQL list agree with each other (both list nothing); `check` on
each row disagrees. Three lists of the canvas cases show it, on SQLite and on Postgres:

| List (principal, permission, type) | Rows `check` allows (each checked with its loaded row) | Listed |
| --- | --- | --- |
| agent AGENT_SESSION for ED, `inherit`, ceiling projects WEB / capabilities `file.edit`; `file:edit` on `file` | HOME, SECRET | none |
| agent AGENT_SESSION for ED, ceiling projects WEB / `project.read`; `project:read` on `file` | HOME, SECRET | none |
| agent AGENT_SESSION for ED, ceiling files HOME / `project.read`; `project:read` on `file` | HOME | none |

The first one also breaks the case "agent acts as its delegator" (HOME is allowed, but not listed).
The two other agent lists of the cases (MIA as delegator; ED on LOCKED, where `agents_allowed` is
false) are empty both ways and conform.

The ceiling is not the cause. A probe with an `inherit` agent of ED with no ceiling at all gives the
same FALSE filter on `project:read` for `file`, while the check of `file:HOME` allows. Without the
ABAC policies the same filter is an args v2 `native:rbac.assignment` term that lists HOME and SECRET.

## Engine path

`explain` of the type-level request (`project:read` on `{ type: 'file' }`, agent for ED, memory world
or SQL world alike):

- `delegation`: "inherit: the models run as user:ED";
- RBAC votes its list term (in the SQL world) or `model_error` (in memory, no list extension);
- ABAC votes `denies: [{ when: TRUE, reason: { code: 'needs_subject', policy: 'agents-disabled' } }]`;
- deny-overrides: residual FALSE.

The policy (design §8.5) is
`{ id: 'agents-disabled', effect: 'deny', actorTypes: ['agent'], permissions: ['*'], when: { attr: 'scope.org.policies.agents_allowed', eq: false } }`.
Its condition reads `scope.org.*`, which ABAC cannot turn into a residual, so on a list request it
denies with `needs_subject` (`packages/authz-abac/src/model/model.ts:182-186`, reason at `:465`). This is B19 as
designed: `AbacModel.listWarnings` (`:294-307`) says "its condition needs the row, so a list request
denies needs_subject". A single check has the row's ancestors, reads `agents_allowed` of ACME (default
true) and lets the RBAC answer stand.

## Who is wrong

Not the case and not the canvas data. The list is narrower than the checks, never wider, so nothing
leaks; but an agent session of canvas (design §8.5 "Agent session") can list no file, project or
branch in any org, also where agents are allowed, and authz-orm's middleware refuses every agent
query (H16: a FALSE residual throws `AccessDenied`). The SQL compiler is not at fault: it never sees
the term. The gap is in the in-memory ABAC model's list answer for a scope-attribute condition, which
the §8.5 config uses on every list-scoped canvas type.

## Proposed change

Option A (recommended): ABAC compiles a `when` over `scope.<type>.<path>` into a residual leaf over
the row's scope attributes instead of `needs_subject`, and authz-orm compiles that leaf to SQL with the
same attribute layers authz-rbac's rule SQL already reads (`authz_scope_attribute` rows plus the
`ScopeAttributeSchema` defaults: `RbacScopeAttributeSource` / `ormRbacScopeLayers` in
`packages/authz-rbac/src/orm/`). The SQL read exists today for RBAC `when` conditions; ABAC needs a
leaf that names it (a `native:` op registered by authz-orm, or a shared core op if the contract owner
prefers; the latter is a frozen-contract change). B19's `listWarnings` then drops this case. The
canvas lists above conform without a pin.

Option B: boot rule 11 (§6.5) also refuses an ABAC policy whose `when` needs the row on a list-scoped
type. That makes the gap loud, but the §8.5 config then fails to boot with authz-orm, so canvas needs
option A or C anyway.

Option C (canvas config only, if A waits): express `agents-disabled` as an RBAC threshold rule, whose
`when` on `scope.org.policies.*` already compiles to SQL. It needs a rule selector on the actor type
(the models run as the delegate under `inherit`); RBAC rule selectors have `principalTypes`, not actor
types, so C also needs a small authz-rbac change, and the reason priority 100 of §16.3 row 2a must
stay. Design §8.5 and §16.3 change.

## Pin

`packages/authz-testing/test/canvas-c6/mismatches.ts`, `LIST_MISMATCHES` (`sqlite` and `postgres`)
held the three list keys above with their exact `listProblems` lines and their cause (a FALSE
residual and the TRUE deny `abac needs_subject (agents-disabled)` of the type-level request). The
default CI set (`B40.list`) ran one of them, so a stale pin failed CI. A4 removed all three: both
maps are empty, and `KnownListMismatch` stays for later pins.

- L4 (authz-orm): the SQL of that leaf (A).

- CV1 (canvas): agent sessions list nothing until this is settled.

## Applied

Lane A4 applied option A in four commits: `58e74a5e2` (core leaf and ABAC), `c5a02d7cc` (folded
scope reads), `d19230fc2` (SQL) and `be45db823` (test fix round), then the canvas commit that
removes the pins. Binding design: `.authz-sdd/A4-design.md`.

### The leaf

- A core native op `native:condition.scope` (`SCOPE_CONDITION_OP`, in
  `packages/authz/src/conditions/`, outside the API snapshot). Args are plain JSON with `v: 1`:
  `{ test: 'true' | 'false', type, path, op, value }` or `{ test: 'fault', type, path }`, where
  `value` is the operand the compiler already resolved (literal, or a principal / actor / env ref).
- `SCOPE_CONDITION_FILTER` answers the leaf in memory with the compiler's own read and comparison
  of the row's scope attribute, so it agrees with `check` by construction. It reads no principal.
- On a request without id whose type is not `$global`, the compiler turns each comparison of
  `scope.<type>.<path>` (type not `$global`) with a literal or principal / actor / env operand into
  `true OR (NOT false AND UNKNOWN)`: TRUE, FALSE or UNKNOWN on the row, as the check's comparison.
  A scope ref as the operand, in function args, or a `$global` request type keep the old path.

### The switch

- `authz.<model>.scopeResiduals` (boolean, schema default `false`) in the ABAC config schema, and
  `AbacModelOptions.scopeResiduals` (wins over config). With it on, ABAC's `init` registers the
  filter and adds the op to its residual capabilities; `listWarnings` drops policies whose every
  row read is a leaf.
- Opt-in because default-on changes what the kit's B19.abac and B39.abac expect of a type-level
  check (`needs_subject` / `model_error` become conditional). Turning it on by default is a kit
  and design decision; this RFC does not make it.

### The fault guard

A check whose scope read faults (no ancestor of the type, unknown node, missing or null
attribute) makes the whole ABAC vote indeterminate: permit FALSE, deny TRUE. The list reproduces
that row by row: per policy, `F_p = scope(p) AND fault`, where `fault` is the OR of the
`{ test: 'fault' }` leaves of the reads the condition makes. It is collected before the policy's
filter folds. `permitWhen = NOT F AND permits`, `denyWhen = F OR denies`; the guard entries carry
the reason `model_error`.

### SQL

- `ConditionScopeOrmCompiler` in authz-rbac (`packages/authz-rbac/src/orm/`), an `OrmNativeCompiler`
  that authz-orm's middleware calls, as for `native:rbac.*`. It reads the attribute with the rule
  SQL's own layers, schema defaults and comparison (moved to `compile/scope-leaf.ts`, rule SQL text
  unchanged). Where SQL cannot decide a value, or cannot read a layer, the list is narrower,
  never wider.
- ABAC lists through authz-orm with the switch on therefore need authz-rbac loaded; without it boot
  rule 4 refuses the route (op not compiled by the adapter). The host must register an
  `RbacScopeAttributeSource` whose schemas are the ones the engine sees: a default only the engine
  has makes SQL fault (narrower, the K1b-1 symptom again), one only SQL has makes lists wider.
- Postgres runs with `jit = off`, as for the rule SQL.

### Folded non-leaf scope reads (also with the switch off)

A policy whose condition reads a scope ref no leaf covers (a scope ref as operand or in function
args, or any scope read with the switch off) and whose filter folded to TRUE or FALSE on a list
request was trusted as folded, while the check of a row still reads that ref and is indeterminate
where it is missing. Such a policy now always takes the needs-subject path: a deny answers
`needs_subject` wherever it applies (B19), a permit makes the vote indeterminate (B39). Lists only
get narrower. This applies with the switch off too. An intersect agent's checks are narrower in
that folded case as well: its check evaluates the delegate's type-level answer against the row
(B06), and that answer is now needs-subject.

### Canvas

Design §8.5's generated config (`test/canvas-c6/config.ts`) now sets
`abac: { scopeResiduals: true, policies }`. The canvas SQL harness registers an
`RbacScopeAttributeSource` with the same `ORG_ATTRIBUTE_SCHEMA` the engine's contributor gives
(`agents_allowed` default true) over authz-orm's layers, so the org layer is readable. The three
pinned lists conform on SQLite and on Postgres; `LIST_MISMATCHES` is empty. Full runs
(`K1B_FULL_LISTS=1`): 58/58 lists conform on each dialect, 52 statements, 49 rows, 6 FALSE
residuals (before: 55 + 3 pinned, 47 statements, 44 rows, 11 FALSE residuals). The two agent lists
that were empty both ways (MIA as delegator; ED on LOCKED, where `agents_allowed` is false) now
run one statement each and still list nothing.

No frozen contract changed (`node scripts/api-snapshot.mjs --check` is clean): the op, the filter
and the compile option live in the core's conditions lane folder, and `compile` keeps its
signature.

### Hand-offs

- Design owner: §8.5 (the config sets `authz.abac.scopeResiduals`), §16.3 row 2a (on a list,
  `agents-disabled` is now row-level SQL, the reason priority 100 unchanged for checks) and the B19
  text (a scope-attribute deny is a list residual when the switch is on).
- Kit owner: B19.abac and B39.abac stay as they are while the switch defaults to false; they change
  if the default flips.
- CV1 (canvas): set `authz.abac.scopeResiduals: true` and register an `RbacScopeAttributeSource`
  that gives the engine's own `scopeAttributeSchemas` over authz-orm's layers (plus `store` layers
  for types without a model).
