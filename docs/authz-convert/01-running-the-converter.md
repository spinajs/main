# Running the converter

`spinajs-authz-convert` reads a 2.x app's compiled config dirs and writes 3.0 config files plus `authz-warnings.md`. Run it once per app, during the config step of the [migration guide](../authz/migration-guide.md#8-steps-for-an-app).

```sh
npx spinajs-authz-convert <config-dir>... [--out <dir>] [--db <file.json>] [--src <dir>] [--self-resources <a,b>] [--force]
```

## How it works

1. `main(argv)` parses the arguments. An unknown option, an option without a value or no config dir ends the run with exit code `1`.
2. `--db` is read by `readDbFacts()` and `--src` is scanned by `scanSources()`, before any config file runs.
3. `convert()` loads the config dirs with `loadLayers()` (see [Config loading and env layers](02-config-loading-and-env-layers.md)) and converts each layer with `convertLayers()`.
4. When any layer holds something the converter refuses, `convert()` throws `ConversionError` with every problem it found. `main()` prints them and returns `1`; no file is written.
5. `main()` checks the `--out` dir. When one of the files it would write already exists and `--force` is not given, it returns `1` and writes nothing.
6. `main()` creates the `--out` dir, writes every file, prints `wrote <path>` for each and a count of manual items, warnings and notes.
7. The exit code is `2` when `authz-warnings.md` lists a "Convert by hand" item, else `0`.

The `bin` entry calls `process.exit()` with that code, because a config file may leave a timer or a socket open.

## Options

| Option | Value | Default | Meaning |
| --- | --- | --- | --- |
| `<config-dir>...` | One or more dirs | (required) | The app's **compiled** config dirs (for example `lib/mjs/config`). Several dirs merge in the order given. |
| `--out` | Dir | `./authz-convert-output` | Where the files go. Created when missing. |
| `--db` | JSON file | none | Rows exported from the 2.x database. See [Database rows](#database-rows---db). |
| `--src` | Dir | none | App sources to scan for `@OrmResource`, `@ResourceOwner` and `@OrmPermission`. See [Source scan](#source-scan---src). |
| `--self-resources` | Comma list | `user` | Resources whose `:own` grants mean the caller's own account (relation `self`). Every other `:own` becomes relation `owner`. See [Grant and role conversion](04-grant-and-role-conversion.md#own-grants-and-relations). |
| `--force` | none | off | Overwrite files that already exist in `--out`. |
| `--help`, `-h` | none | | Print the usage text and exit with `0`. |

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Converted. Nothing is left for a person (warnings and notes may still be listed). |
| `2` | Converted, with keys left to convert by hand. Read the "Convert by hand" section of `authz-warnings.md`. |
| `1` | Refused or failed. Nothing was written. |

## Output

| File | Holds |
| --- | --- |
| `authz-generated.ts`, `authz-generated.<env>.ts` | `authz.rbac.roles`, `authz.permissions`, principals, admin guard, impersonation, token role policy. |
| `users-generated.ts`, `users-generated.<env>.ts` | `users.user`, `users.email`, `users.actions`. |
| `authn-generated.ts`, `authn-generated.<env>.ts` | Strategies, local password, session, MFA, token, throttle. |
| `authz-warnings.md` | What to convert by hand, behaviour changes, notes. See [Findings and refusals](05-findings-and-refusals.md). |

- One file per root and layer. A root the layer does not set gets no file; `authz-warnings.md` is always written.
- `<env>` is the env suffix of the 2.x files (`rbac.local.js` gives `authz-generated.local.ts`).
- The base names hold no dot: the 3.0 loader reads `name.js` as a common file and `name.<env>.js` as an env file, so `authz.generated.ts` would never load.
- Each file is a TypeScript module with a `export default { <root>: { ... } }` literal and a two-line header naming the input dirs and the layer.
- Copy the files into the app's config dir and compile them with the rest of the config.

```ts
// Generated by spinajs-authz-convert from lib/mjs/config (common files).
// Read authz-warnings.md before you use it.
export default {
  authz: {
    principals: { anonymous: { enabled: false } },
    rbac: { defaultRoles: ['user'], roles: { user: { grants: ['Doc:read'] } } },
    permissions: { 'Doc:read': {} },
  },
};
```

## Database rows (`--db`)

The converter never connects to the database. It reads a JSON file exported from the 2.x database. 3.0 starts from an empty database and carries none of these rows, so export them before you leave 2.x. The export queries are in the [migration guide](../authz/migration-guide.md#42-export-the-database-rows-first---db).

```json
{
  "users":  [{ "Id": 1, "Login": "bob", "Role": "acme.salesman,partner.backoffice" }],
  "tokens": [{ "Id": 1, "Roles": "system", "ExpiresAt": null }]
}
```

- `users[].Role` and `tokens[].Roles` may be an array, a JSON array in a string, or a comma list. `null` or `""` is no role.
- A row is named by `Login`, else `Id`, else `Uuid`, else its index.
- Either list may be missing. A file of another shape stops the run with exit code `1`.

With the rows the converter:

- writes `assignable: false` on roles no user or token holds and that other roles only extend (see [Grant and role conversion](04-grant-and-role-conversion.md#assignable-roles---db));
- lists users holding several roles (`roles-together`), users or tokens whose role list 2.x voided (`roles-voided`), held roles no config file defines (`held-unknown-role`) and tokens without expiry (`token-no-expiry`).

## Source scan (`--src`)

`scanSources(dir)` reads every `.ts`, `.js`, `.mjs` and `.cjs` file under the dir, skipping `.d.ts`, `node_modules` and dot dirs. It does not run them. It collects:

- the resource of every `@OrmResource('X')` and the files declaring it;
- the files that use `@ResourceOwner()`;
- the scope names of `@OrmPermission(Model, 'scope')` (`default` when the scope is left out).

The converter then checks each `:own` relation against the models (`owner-relation`, `scope-relation` findings). Without `--src` every `owner` relation gets a warning to check the model by hand. The output files do not change.

## Important behaviour

- The converter **runs** the app's config files, twice or more: once in the converter process, then in child processes under other `NODE_ENV` values. A config file with side effects runs them each time.
- A refusal is all or nothing: `ConversionError` lists the problems of every layer, then the run stops.
- `--out` is checked only for the files of this run; other files in the dir stay.
- Only `rbac.*` is converted. Other roots in the same files (`queue`, `system`, `http` and the rest) are not written anywhere.

## Best practices

- Build the app first and point the converter at the compiled dir; a dir with `.ts` sources is refused.
- Export the `--db` rows from the 2.x database before the upgrade; the 3.0 database holds none of them, so the role-holder checks have no other source.
- Pass `--src` so the warnings name the models that need `@Owner()` instead of every `:own` resource.
- Write into an empty `--out` dir and diff it against the app's config, instead of `--force` into the config dir.
- Treat exit code `2` as unfinished: the "Convert by hand" items may fail the boot.

## Examples

### Convert an app with two config dirs into a review dir

```sh
npx spinajs-authz-convert lib/mjs/config lib/mjs/config-overrides \
  --out build/authz-convert --db exports/rbac-facts.json --src src
```

### Run the command from a script

```ts sample
import { main } from '@spinajs/authz-convert';

export async function convertInCi(): Promise<void> {
  const lines: string[] = [];
  const code = await main(['lib/mjs/config', '--out', 'build/authz-convert', '--force'], (line) => lines.push(line), (line) => lines.push(`ERROR ${line}`));
  if (code === 1) throw new Error(lines.join('\n'));
  if (code === 2) console.warn('authz-convert left keys to convert by hand; see build/authz-convert/authz-warnings.md');
}
```
