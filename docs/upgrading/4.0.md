# Upgrading to 4.0

4.0 resets the foundation: ESM only, Node 22 or newer, one flat `lib/` output, `application/problem+json` error bodies, and a changesets-based release process. Most of the mechanical changes are applied by a codemod.

## Run the codemod first

```bash
npm i -D @spinajs/codemods
npx spinajs upgrade --to 4 --dry-run   # list the files that would change
npx spinajs upgrade --to 4             # rewrite them
```

Run it from the package root (the directory with `tsconfig.json`). It covers the `lib/mjs` import paths, `DI.setESMModuleSupport()` and the `typeof module` cjs/mjs switch, and leaves a `// TODO(spinajs-4)` above every `@HandleException` usage. Everything else on this page is manual. `@spinajs/codemods` is an optional peer dependency of `@spinajs/cli`; without it `spinajs upgrade` tells you to install it.

## ESM only, Node 22

- Node 22 or newer is required: every package has `engines.node >=22.0.0`. CI tests on 22 and 24.
- Packages are ESM only (`"type": "module"`). `require('@spinajs/...')` no longer resolves; use `import`. The `exports` maps have no `require` condition.
- Your own app must be ESM too: `"type": "module"` in `package.json`, `module` and `moduleResolution` set to `node16` or `nodenext`, and `.js` extensions on relative imports.

## `lib/` paths

Packages build into `lib/` instead of `lib/mjs` and `lib/cjs`.

| Before | After |
| --- | --- |
| `@spinajs/http/lib/mjs/index.js` (or `/index`) | `@spinajs/http` |

Package `exports` maps expose only the package root (`.`), so a deep path such as `@spinajs/orm/lib/config/orm.js` does not resolve under `node16`/`nodenext`. The codemod therefore works like this:

- `lib/mjs` or `lib/mjs/index.js` becomes the package root.
- A deep path becomes the package root only when it is a named import or `export { ... } from` and the installed package's root entry exports every one of those names.
- Any other deep path (side-effect, default or namespace import, `import()`, `require()`, names the root does not export) and every `lib/cjs` path is left as is, gets a `// TODO(spinajs-4)` line above it and is listed at the end of the run. For a file-system lookup such as a config directory, keep the path and build it without `mjs`; otherwise import from the package root.

Static imports, `export ... from`, `import()`, `require()`, `import x = require()` and `typeof import()` with a string literal are covered. Check by hand anything that builds such a path from parts, for example a `system.dirs.*` override that joins `'lib'`, `'mjs'` and a folder: drop the `mjs` segment. The codemod removes the common `typeof module !== 'undefined' ? 'cjs' : 'mjs'` form of this when it is a call argument or a plain string; where dropping the segment would leave an empty path part (a template or a concatenation) it leaves the expression and lists it.

The codemod visits only files that `tsconfig.json` selects through `include`/`files`, JS and CJS files among them even without `allowJs`. Files outside it (for example a root `config.cjs`) must be added to `include` for the run. A file a transform fails on is left untouched and listed; the rest of the run continues.

## `DI.setESMModuleSupport()` is deprecated

It is a no-op that logs a deprecation warning and is removed in 5.0. Delete the call.

## Error bodies are `application/problem+json`

HTTP error responses follow RFC 9457. The body holds `type`, `title`, `status`, `detail`, `instance` and, when present, `code` or `errors`.

- Read `detail` instead of `message`, and `errors` instead of `details` / `parameter`.
- Other properties of an exception are no longer copied into the body. List the ones a client needs in `http.errors.includeFields`, or declare them in a static `problemFields` on the exception class (preferred).
- The stack is added only when `http.errors.includeStack` is `true` outside production (default `false`).
- In production an unmapped 500 answers `detail: "Internal server error"` without `code`; the message stays in the log.
- `ProblemDetails`, `toProblem` and `PROBLEM_DETAILS_SCHEMA` are exported from `@spinajs/http`. The http-swagger error component is now `ProblemDetails`.

`@HandleException` handlers keep working; the codemod only marks them so you re-check the body they produce.

## Config arrays replace the default

An array your app configures now replaces the array a package config sets, as a scalar does. 3.x concatenated every array of every source.

```js
// @spinajs/http-socket ships  http: { socket: { transports: ['websocket', 'polling'] } }
// config/http.js in your app:
export default { http: { socket: { transports: ['websocket'] } } };

// 3.x: ['websocket', 'polling', 'websocket'], which the uniqueItems schema check refuses
// 4.0: ['websocket']
```

Which merge replaces an array:

| Merge | Arrays |
| --- | --- |
| Package config files (`node_modules/@spinajs/*/lib/config`, or the manifest's `configFiles`) among themselves | concatenate |
| `__configuration__` DI values | concatenate |
| Your own config files, also an environment file over a common file | replace |
| `onLoad()`, `StaticConfigurationSource`, `ConfiguratioDbSource` and every other `ConfigurationSource`, `mergeSource()` | replace |
| `configuration.merge(path, value)` | concatenate |

Some arrays collect entries from several packages and your app. They keep concatenating in every merge, so your entries are added to the packages' entries. The list is exported as `COMPOSED_CONFIG_ARRAYS` from `@spinajs/configuration`:

- `system.dirs.*`
- `fs.providers`, `queue.connections`, `http.Static`, `logger.filters`
- every array of an RBAC role (`authz.rbac.roles.<role>.grants`, `extends`, `revoke`, `scopeTypes`) and `authz.rbac.serviceRoles.<service>`
- `authz.abac.policies`, `authz.admin.guard.keepHolders`, `authz.fields.neverRead`, `validation.strict.idPrefixes`
- the `__file__` list of every section

What to check:

- **`http.middlewares`.** A config file or `onLoad()` that lists one middleware now drops every shipped one: `helmet`, the JSON, form and text body parsers, the cookie parser and `compression`. The app loses its security headers and `req.body` without an error. Add to the list with `merge()` (below), or list the whole array.
- A config file or `onLoad()` that listed only the entries it adds to another package array (`http.socket.transports`, `intl.locales`, `telemetry.buckets`, `templates.*.static.portRange`, ...) now drops the package's entries. List the whole array.
- An environment file (`*.prod.js`) that added entries to an array of the common file now replaces it. List the whole array there too.
- To add to a package array instead, call `merge()`, for example in a `configure()` hook: `this.merge('http.middlewares', [requestId])`. `merge()` also appends to an array stored at the path itself now; it used to overwrite it index by index.
- `BaseFileSource.configFiles()` returns `{ file, arrays }` entries instead of paths, and `load()` takes an optional object to merge into. A subclass that overrides `configFiles()` must return the new shape.

## Authentication (`@spinajs/authn`)

`authn.mfa.policy.methods` and `authn.mfa.policy.forceForRoles` are no longer shipped as defaults; the schema defaults apply (`['password']` and `[]`). Config arrays used to concatenate, so a shipped value could not be removed. Now an app that sets `methods` gets exactly its list: a configured list replaces the default.

If you set `methods` without `password` (for example `['oidc']`), password logins no longer require an MFA step. Write `['password', 'oidc']` to keep it. A malformed string `forceForRoles` is now refused instead of being concatenated into a list.

## Removed: `@spinajs/queue-orm-transport`

The package is removed from the monorepo and is no longer published. The database-backed queue transport is not available in 4.0. Use another transport (for example `@spinajs/queue-stomp-transport`) or stay on 3.x if you depend on it.

## DI

- `asValue` / `asMapValue` bindings are registrations. `clearCache()` keeps them; `clearRegistry()` and `clear()` drop them. Bootstrappers that re-registered a value after `clearCache()` can be deleted.
- `register(X).as(Y, { replace: true })` makes a re-registered class the last (winning) registration; without the option the first position is kept, as before.
- `DI.child({ isolateSingletons: true })` creates a child that owns every singleton it resolves. `container.snapshot()` / `container.restore(snapshot)` capture and put back registrations, values, cached instances and listeners.
- `restore()` disposes the services created since the snapshot against the live state, then swaps the snapshot back. When resolutions keep starting while it disposes (a poller, a reconnect loop), the state is still put back and `restore()` rejects with `RestoreIncomplete`, which names what was still resolving.

## Tests

`@spinajs/testing` replaces per-package `TestConfiguration` registration and `test/support/config-boot.ts` copies: `createTestApp`, `useTestApp`, `configurationViolations`, `readingFrom`, `fakeContainer`, `setPastSchema`, `disposeTestApps`.

- Only one root app can be live at a time, and the slot is claimed before the boot starts: a second root `createTestApp` rejects at once, naming the holder. Use `scope: 'child'` for apps side by side.
- A root boot that does not finish within `bootTimeout` (default 30000 ms; `useTestApp` uses 90% of the hook timeout; `0` or `Infinity` disables it) is abandoned and root is restored, so the next suite boots cleanly.
- `dispose()` restores root and rejects with `RestoreIncomplete` when a service keeps resolving while it is disposed.

## Release process

Releases are moving to [changesets](https://github.com/changesets/changesets) with one fixed group, `@spinajs/*`: every package gets the same version, bumped by the highest change level in the release. Automated releases are not enabled yet; the existing release scripts (`scripts/bump-all.mjs`, `scripts/publish-all.mjs`) and workflow are still in use until they are.

Once enabled, the intended flow is:

- Every pull request that changes behaviour adds a `.changeset/*.md` entry (`npx changeset`).
- A scheduled run (or a manual trigger) opens a "version packages" pull request that bumps versions, writes the changelogs and updates the lockfile.
- Merging that pull request publishes to npm and tags the release.
