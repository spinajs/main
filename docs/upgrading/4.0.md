# Upgrading to 4.0

4.0 resets the foundation: ESM only, Node 22 or newer, one flat `lib/` output, `application/problem+json` error bodies, and a changesets-based release process. Most of the mechanical changes are applied by a codemod. For the features 4.x adds and a path from build to deploy, see [What is new in 4.x](../whats-new-4.0.md).

## Run the codemod first

```bash
npm i -D @spinajs/codemods
npx spinajs upgrade --to 4 --dry-run   # list the files that would change
npx spinajs upgrade --to 4             # rewrite them
```

Run it from the package root (the directory with `tsconfig.json`). It covers the `lib/mjs` import paths, `DI.setESMModuleSupport()` and the `typeof module` cjs/mjs switch, and leaves a `// TODO(spinajs-4)` above every `@HandleException` usage. Everything else on this page is manual. `@spinajs/codemods` is an optional peer dependency of `@spinajs/cli`; without it `spinajs upgrade` tells you to install it.

## ESM only, Node 22

- Node 22 or newer is required: every package has `engines.node >=22.0.0`. CI tests on 22 and 24.
- Packages are ESM only (`"type": "module"`). `require('@spinajs/...')` no longer resolves; use `import`. The `exports` maps have no `require` condition.
- Your own app must be ESM too: `"type": "module"` in `package.json`, `module` and `moduleResolution` set to `node16` or `nodenext`, and `.js` extensions on relative imports.

## `lib/` paths

Packages build into `lib/` instead of `lib/mjs` and `lib/cjs`.

| Before | After |
| --- | --- |
| `@spinajs/http/lib/mjs/index.js` (or `/index`) | `@spinajs/http` |

Package `exports` maps expose only the package root (`.`), so a deep path such as `@spinajs/orm/lib/config/orm.js` does not resolve under `node16`/`nodenext`. The codemod therefore works like this:

- `lib/mjs` or `lib/mjs/index.js` becomes the package root.
- A deep path becomes the package root only when it is a named import or `export { ... } from` and the installed package's root entry exports every one of those names.
- Any other deep path (side-effect, default or namespace import, `import()`, `require()`, names the root does not export) and every `lib/cjs` path is left as is, gets a `// TODO(spinajs-4)` line above it and is listed at the end of the run. For a file-system lookup such as a config directory, keep the path and build it without `mjs`; otherwise import from the package root.

Static imports, `export ... from`, `import()`, `require()`, `import x = require()` and `typeof import()` with a string literal are covered. Check by hand anything that builds such a path from parts, for example a `system.dirs.*` override that joins `'lib'`, `'mjs'` and a folder: drop the `mjs` segment. The codemod removes the common `typeof module !== 'undefined' ? 'cjs' : 'mjs'` form of this when it is a call argument or a plain string; where dropping the segment would leave an empty path part (a template or a concatenation) it leaves the expression and lists it.

The codemod visits only files that `tsconfig.json` selects through `include`/`files`, JS and CJS files among them even without `allowJs`. Files outside it (for example a root `config.cjs`) must be added to `include` for the run. A file a transform fails on is left untouched and listed; the rest of the run continues.

## `DI.setESMModuleSupport()` is deprecated

It is a no-op that logs a deprecation warning and is removed in 5.0. Delete the call.

## Error bodies are `application/problem+json`

HTTP error responses follow RFC 9457. The body holds `type`, `title`, `status`, `detail`, `instance` and, when present, `code` or `errors`.

- Read `detail` instead of `message`, and `errors` instead of `details` / `parameter`.
- Other properties of an exception are no longer copied into the body. List the ones a client needs in `http.errors.includeFields`, or declare them in a static `problemFields` on the exception class (preferred).
- The stack is added only when `http.errors.includeStack` is `true` outside production (default `false`).
- In production an unmapped 500 answers `detail: "Internal server error"` without `code`; the message stays in the log.
- `ProblemDetails`, `toProblem` and `PROBLEM_DETAILS_SCHEMA` are exported from `@spinajs/http`. The http-swagger error component is now `ProblemDetails`.

`@HandleException` handlers keep working; the codemod only marks them so you re-check the body they produce.

## Config arrays replace the default

An array your app configures now replaces the array a package config sets, as a scalar does. 3.x concatenated every array of every source.

```js
// @spinajs/http-socket ships  http: { socket: { transports: ['websocket', 'polling'] } }
// config/http.js in your app:
export default { http: { socket: { transports: ['websocket'] } } };

// 3.x: ['websocket', 'polling', 'websocket'], which the uniqueItems schema check refuses
// 4.0: ['websocket']
```

The config files now merge in two layers. Package config files of every format (`.js`, `.cjs`, `.json`), common then environment files, come first. Your own config files, `src/config` included, common then environment files, come on top.

| Merge | Arrays |
| --- | --- |
| Package config files (`node_modules/@spinajs/*/lib/config`, or the manifest's `configFiles`) among themselves | concatenate |
| `__configuration__` DI values, which lead the package layer | concatenate |
| Your own config files, over the packages and over each other, also an environment file over a common file | replace |
| `onLoad()`, `StaticConfigurationSource`, `ConfiguratioDbSource` and every other `ConfigurationSource`, `mergeSource()` | replace, in `Order` |
| `configuration.merge(path, value)` | concatenate |

Sources merge in `Order`. `StaticConfigurationSource(cfg)` defaults to `Order` `0`, below the file sources (`1`), so a package default replaces its array, where 3.x kept both. Give it an `Order` above `1` to override a package array: `StaticConfigurationSource(cfg, 10)`.

The layers move scalars too:

- A value in `<cwd>/src/config` now wins over a package default. It used to merge before the packages, so the package won.
- A package environment file (`*.prod.js`) no longer wins over your common file. It used to, because environment files merged after every common file.
- A package JSON file no longer wins over your JS config. Between your own files, JSON still wins over JS.
- In a composed array your entries now follow every package entry, package environment files included.
- A `__configuration__` DI value is a package default. It used to merge after `onLoad()` and win every scalar; now your files, a source above the file sources and `onLoad()` win. Use `configuration.set()` for a value that must win at runtime, also in the browser.

Some arrays collect entries from several packages and your app. They keep concatenating in every merge, so your entries are added to the packages' entries. The list is exported as `COMPOSED_CONFIG_ARRAYS` from `@spinajs/configuration`:

- `system.dirs.*`
- `fs.providers`, `queue.connections`, `http.Static`, `logger.filters`
- the `grants`, `extends` and `revoke` of an RBAC role (`authz.rbac.roles.<role>.grants`) and `authz.rbac.serviceRoles.<service>`
- `authz.abac.policies`, `authz.admin.guard.keepHolders`, `authz.fields.neverRead`, `validation.strict.idPrefixes`
- the `__file__` list of every section

What to check:

- **`http.middlewares`.** A config file or `onLoad()` that lists one middleware now drops every shipped one: `helmet`, the JSON, form and text body parsers and the cookie parser. (Compression is not in the list any more: it is the `Compression` server middleware, switched by `http.compression.enabled`.) The app loses its security headers and `req.body`, and `HttpServer` logs one warning at boot that names what is missing. Keep the defaults with `middlewares: [...defaultMiddlewares(), requestId]`, or add to the list with `merge()` (below). The warning recognises the shipped handlers by a tag, so your own `helmet()` also triggers it: ignore it then. A list with its own `cookieParser()` needs the secret too, `cookieParser(secret)`: 3.x kept the shipped parser next to it, and without the secret the signed session cookie is not read and every session answers 401.
- **`http.upload.middlewares`.** The shipped list is `['FileInfoMiddleware']`. A list of only your own upload middlewares drops it, and a route with `fileInfo: true` gets no `file.Info`. List it with yours: `upload: { middlewares: ['FileInfoMiddleware', MyUploadMiddleware] }`.
- A config file or `onLoad()` that listed only the entries it adds to another package array (`http.socket.transports`, `intl.locales`, `telemetry.buckets`, `templates.*.static.portRange`, ...) now drops the package's entries. List the whole array.
- An environment file (`*.prod.js`) that added entries to an array of the common file now replaces it. List the whole array there too.
- To add to a package array instead, call `merge()`, for example in a `configure()` hook: `this.merge('http.middlewares', [requestId])`. `merge()` also appends to an array stored at the path itself now; it used to overwrite it index by index.
- `authz.rbac.roles.<role>.scopeTypes` is a value: your list replaces the shipped one, where 3.x added to it. It can now narrow a role.
- **Files generated by `spinajs-authz-convert`.** A `*-generated.<env>.ts` file written on 3.x holds only what the environment added to an array. Loaded by 4.0 it replaces the common list instead: with `protectedRoles: ['finance']` there, the `system` and `auditor` holders of the common file can be impersonated in that environment. Run the converter again, or add the common entries to every array in those files.
- `BaseFileSource.configFiles()` returns `{ file, arrays }` entries instead of paths, and `projectConfigDirs()` returns one list. A subclass that overrides `configFiles()` must return the new shape. A file source of your own format stays a plain source unless it implements `LoadLayers()` (see [Config files](../configuration/03-config-files.md#basefilesource-custom-file-format)).
- A subclass of `JsFileSource` or `JsonFileSource` that overrides only `Load()`, for example to decrypt values, loads as if it did not: the boot calls `LoadLayers()` of a file source, not `Load()`. The boot logs a warning naming the class. Override `LoadLayers()` instead and change the layers it returns.

## Authentication (`@spinajs/authn`)

`authn.mfa.policy.methods` and `authn.mfa.policy.forceForRoles` are no longer shipped as defaults; the schema defaults apply (`['password']` and `[]`). Config arrays used to concatenate, so a shipped value could not be removed. Now an app that sets `methods` gets exactly its list: a configured list replaces the default.

If you set `methods` without `password` (for example `['oidc']`), password logins no longer require an MFA step. Write `['password', 'oidc']` to keep it. A malformed string `forceForRoles` is now refused instead of being concatenated into a list.

One client address ([Client IP](../http/17-client-ip-and-trust-proxy.md#one-client-address-with-authn)):

- `@spinajs/authn-http` registers `AuthnRealIp` over http's `RealIp`: `authn.http.trustProxy` now also decides `req.storage.realIp`, so `@RateLimit`, `http.throttle`, `@Ip()` and the same-origin and CSRF guards count the client authn counts. An app that set only `authn.http.trustProxy` used to rate limit every client as the proxy. `AuthnRealIp` runs at Order 0.
- `ClientIp` copies `req.storage.realIp` and parses no trust. A subclass of `ClientIp` that changed the address moves to a subclass of `AuthnRealIp` registered `.as(RealIp)`. A `RealIp` subclass of your own replaces `AuthnRealIp`: extend `AuthnRealIp` instead, or `authn.http.trustProxy` stops counting.
- `authn.throttle.ipv6Prefix` has no shipped default: unset, it takes `http.throttle.ipv6Prefix`, else 64. Nothing changes unless you set only the http key.
- The boot warns when `authn.http.trustProxy` and `http.trustProxy` are both set and differ, and when `authn.throttle.ipv6Prefix` differs from `http.throttle.ipv6Prefix`. Keep one of each, preferably the http key.

## HTTP middlewares

Route and server middlewares share one contract: `HttpMiddleware`, with the optional context hooks `onBefore(ctx)`, `onAfter(ctx)`, `onFinish(ctx)` and `onAround(ctx, proceed)`. `RouteMiddleware` and `ServerMiddleware` extend it. The migration tables are in [Route middlewares](../http/14-route-middlewares.md#migrating-from-the-positional-hooks) and [Server middlewares](../http/15-server-middlewares.md#migrating-from-before-and-after).

Route middlewares:

- The hooks take one context object: `onBefore(req, res, route, controller)` becomes `onBefore(ctx)` and `onAfter(req, res, route, controller)` becomes `onAfter(ctx)`. The positional signatures no longer compile.
- `onResponse` is removed. A middleware that still defines it, itself or through a base class, fails the route registration with `RouteRegistrationException`. Move the code to `onAfter(ctx)`: the reply is `ctx.response`, its body `ctx.response.data`.
- `onAfter` runs for every reply of a matched route, error replies included (`ctx.error` is set), and in the exact reverse of the entry order: a route's middleware before the controller's, an inner one before an outer one. A hook meant for successful replies only returns early when `ctx.error !== undefined`.
- `onBefore` may return a `Response`: it answers the request, and the later middlewares and the action do not run. Any other value except `undefined` and `null` fails the request with a 500.
- `onFinish(ctx)` replaces a `res.on('finish')` listener registered in `onBefore`; `ctx.aborted` is `true` when the client went away.
- New: `http.routes.middlewares` mounts route middlewares on every route of the app ([Global route middlewares](../http/14-route-middlewares.md#global-route-middlewares)).

Server middlewares:

- `before()` and `after()` are removed. A server middleware, or a `NotFoundMiddleware` or `ErrorHandlerMiddleware` replacement, that still defines either fails `HttpServer.resolve()` with an `InvalidOperation` naming the class. Use the hooks, `isEnabled()` (called once at mount, `false` mounts nothing), `resolve()` for settings and `handler()` for a third-party Express handler.
- `NotFoundMiddleware` and `ErrorHandlerMiddleware` are no longer server middlewares but the fixed tail of `HttpServer`. A replacement overrides `reply(req)` and `reply(error, req)`, which return the `Response`.
- `HttpServer` creates `req.storage` itself, as its first handler. `RequestStorage` is deprecated and no longer registered; an `Order` chosen to run after it needs no change.
- `compression` is no longer in `defaultMiddlewares()`. It is the `Compression` server middleware, switched off with `http.compression.enabled: false`. A `compression()` in your own `http.middlewares` list is redundant next to it.
- `x-response-time` (`ResponseTime`) and `Server-Timing` (`ServerTiming`) are set in `onAfter`: static files and replies an action wrote to `res` itself no longer get them.
- `CsrfGuard.refuse()`, `SameOriginGuard.refuse()` and `CsrfOriginGuard.refuse()` (`@spinajs/authn-http`) return the refusal `Response` instead of writing `res`.
- A subclass of a shipped middleware that wrapped `super.before()` overrides a hook and calls `super.onBefore(ctx)`, or overrides the decision method the middleware offers: `allowance()` (CORS), `shouldLog()` (`AccessLog`), `refuse()`, `proxyTrust()` (`RealIp`).

Middlewares of other packages:

- `@spinajs/telemetry`: a `TelemetryMiddleware` subclass overrides `record(ctx)` instead of `onFinish(req, res)` and `routeLabel(ctx)` instead of `routeLabel(req)`; it skips a request by overriding `onBefore(ctx)` without calling `super.onBefore(ctx)` ([Customizing the request middleware](../telemetry/04-customizing-the-request-middleware.md)).
- `@spinajs/intl-http`: an `IntlHttpMiddleware` subclass that wrapped `super.before()` overrides `detectLanguage(req)` ([Request language](../intl-http/01-request-language.md)).
- `@spinajs/authz-http`: `AccessEpochMiddleware` sets `X-Access-Epoch` in `onAfter`, from the principal as it is when the reply leaves. Error replies and the 404 get it too; static files and replies an action wrote to `res` itself do not.
- `@spinajs/authn-http`: `AuthnMiddleware`, `ClientIp` and `CsrfOriginGuard` run on the hooks; a subclass overrides `onBefore(ctx)` or `refuse()` instead of wrapping `super.before()`.

## From 3.0.24 to 3.0.26

4.0 carries the breaking changes of the late 3.x releases.

- **`Orm.resolve()` applies the `Migration.OnStartup` migrations.** Resolve the `Orm`, not `OrmMigrator`: `DI.resolve(OrmMigrator)` migrates nothing. The `data()` seeds run once the `Orm` is cached, and `await orm.Migrator.ready()` waits for them. A migration tool calls `resolveMigrationTool()`. `AwaitsStartupMigration` is removed. With a manifest in effect this applies to the migrations it lists ([Migrating on startup](../orm/10-migrations.md#migrating-on-startup-diresolveorm)).
- **Only `authz.models` activates authorization models**, by class name, and `authz.domains.<name>.models` per domain. `registerRbac`, `buildRbac`, `useRbac` and `authz.use` are removed. Root without `authz.models` has no model, so every check denies. `authz.models` is a config value, not a composed array: an environment file that sets it replaces the list ([Registering the shipped models](../authz/04-host-boot-and-configuration.md#registering-the-shipped-models)).

## Removed: `@spinajs/queue-orm-transport`

The package is removed from the monorepo and is no longer published. The database-backed queue transport is not available in 4.0. Use another transport (for example `@spinajs/queue-stomp-transport`) or stay on 3.x if you depend on it.

## DI

- `asValue` / `asMapValue` bindings are registrations. `clearCache()` keeps them; `clearRegistry()` and `clear()` drop them. Bootstrappers that re-registered a value after `clearCache()` can be deleted.
- `register(X).as(Y, { replace: true })` makes a re-registered class the last (winning) registration; without the option the first position is kept, as before.
- `DI.child({ isolateSingletons: true })` creates a child that owns every singleton it resolves. `container.snapshot()` / `container.restore(snapshot)` capture and put back registrations, values, cached instances and listeners.
- `restore()` disposes the services created since the snapshot against the live state, then swaps the snapshot back. When resolutions keep starting while it disposes (a poller, a reconnect loop), the state is still put back and `restore()` rejects with `RestoreIncomplete`, which names what was still resolving.

## `typescript` and `glob` are optional peers

`@spinajs/http` no longer installs `typescript`, and `@spinajs/reflection` no longer installs `typescript` or `glob`. Both are optional peer dependencies, so `npm install` does not bring them in.

**`typescript` (`@spinajs/http`).** Route parameter names come from the manifest when one is in effect (`system.manifest.mode` `prefer` or `require`), else from the TypeScript controller cache. The cache imports `typescript` only to parse a controller it has no entry for. An app in `off` mode (the default) does one of these:

- installs `typescript` as a dependency of the app (a `devDependency` is not enough when the production install omits dev dependencies);
- builds the controller cache ahead of time with `spinajs http:controllers:cache` (for example in the image build, where `typescript` is present) and ships the `__fs_controller_cache__` directory: a boot whose entries all exist never loads the compiler;
- switches to the manifest: `spinajs build`, then `system.manifest.mode` `prefer` or `require`.

Without any of them, the first controller the cache has to parse fails the boot with `NoControllerMetadata`, which names the optional peer and these three ways out.

**`glob` (`@spinajs/reflection`).** `@ResolveFromFiles` and `@ListFromFiles` import `glob` on the first directory scan. An app that scans directories (`off` mode, or a `prefer` mode section the manifest does not cover) installs `glob` `^8`, or lists from the manifest. Without it the first scan fails with `ReflectionException`, naming the optional peer. Today `@spinajs/configuration` (and `@spinajs/intl`, `@spinajs/orm`, `@spinajs/validation`) still depend on `glob`, so a usual npm install resolves it anyway; do not rely on that, it is not a guarantee under strict layouts such as pnpm.

**`typescript` (`@spinajs/reflection/typescript`).** `TypescriptCompiler` needs `typescript` installed next to `@spinajs/reflection`.

Other changes in the same area:

- `DefaultControllerCache` moved off the package root: `import { DefaultControllerCache } from '@spinajs/http/cache'`. The documentation types (`IMethodDoc`, `IControllerDocumentation`, ...), `parseFnParamNames` and `isOnDiskSource` stay on the root.
- In `require` mode a controller with a source file that the manifest does not list fails registration with `NoControllerMetadata`. Rebuild the manifest after adding a controller.
- `spinajs build` no longer loads an app class that discovery would not load. A controller outside `system.dirs.controllers` was mounted in `prefer` and `require` and is not any more, unless something registers it; the same goes for socket controllers, schedules, commands and migrations. Each is reported as a `CMP006` warning: declare its folder in `system.dirs` or move it. A build where no configured dir maps into the app now fails with `CMP007`; `--allow-no-dirs` builds a deliberate no-dirs app. Build with the `APP_ENV`, `--app`, `--apppath` and `--config-path` of the deployment, because the manifest reflects that config. See [The app's own classes](../manifest/README.md#the-apps-own-classes).
- **Rebuild the manifest after upgrading.** A manifest built before `mountedBy` existed has no such flags, so it keeps mounting every class it lists until `spinajs build` runs again. `MANIFEST_VERSION` stays 2 because the field is additive; nothing refuses the old file.
- A manifest built with `spinajs build --no-schemas` has no payload schemas for the app's socket contracts. Such an app used to run its contracts unvalidated without a word. Now a `require` boot fails and names the contracts, and `prefer` logs one warning naming them. Build without `--no-schemas` when the app binds socket contracts.
- A controller's manifest entry now lists the routes it inherits from base classes of its package, with the subclass's path and generic types. After rebuilding, request validation of an inherited generic route uses the DTO the subclass binds: `POST /articles/create` on `ArticlesController extends BaseCrud<ArticleDto, CreateArticleDto>` is validated against `CreateArticleDto`. This fixes a bug: the old schema came from the unbound type parameter and rejected every non-empty body with a 400, so valid requests now pass and requests that do not match the DTO (including `{}`) get a 400. A subclass without its own `@BasePath` is recorded at the base path it inherits, so the first `spinajs manifest:diff` against an older manifest shows its routes at corrected paths and the inherited routes as added. The report warns when base and head come from different compilers: rebuild the base with the new compiler to compare like with like. `spinajs doctor` now checks inherited routes too, so a subclass of a guard-less base such as `UploadController` without `@Access`, `@Policy`, `@AllowAnonymous` or `@Public` fails HTTP002.
- `TypescriptCompiler` moved to `import { TypescriptCompiler } from '@spinajs/reflection/typescript'`. Importing `@spinajs/reflection` loads neither `typescript` nor `glob`; `glob` is imported on the first directory scan.

## CLI

- `spinajs` run where no application is found fails with `error: no application found in <dir>` and a non-zero exit code when it is given a command. It used to exit 0 having done nothing, so a script that ran `spinajs migrate up` from the wrong directory passed. Run it from the application directory.

## Tests

`@spinajs/testing` replaces per-package `TestConfiguration` registration and `test/support/config-boot.ts` copies: `createTestApp`, `useTestApp`, `configurationViolations`, `readingFrom`, `fakeContainer`, `setPastSchema`, `disposeTestApps`.

- Only one root app can be live at a time, and the slot is claimed before the boot starts: a second root `createTestApp` rejects at once, naming the holder. Use `scope: 'child'` for apps side by side.
- A root boot that does not finish within `bootTimeout` (default 30000 ms; `useTestApp` uses 90% of the hook timeout; `0` or `Infinity` disables it) is abandoned and root is restored, so the next suite boots cleanly.
- `dispose()` restores root and rejects with `RestoreIncomplete` when a service keeps resolving while it is disposed.

## Adopting the 4.x tooling

None of this is required to run on 4.0, and none of it is done by the codemod. Do it after the app boots on 4.0, in this order:

1. **Build a manifest.** Compile, then `spinajs build`, and read what it reports ([What is new in 4.x](../whats-new-4.0.md#from-build-to-a-running-app), [`build`](../cli/08-command-reference.md#build)). Start with `system.manifest.mode` `off` or `prefer`.
2. **Run `spinajs doctor`** and fix its errors ([spinajs doctor](../compiler/doctor.md)). Rule `HTTP002` reports a route with no `@Access`, `@Policy`, `@AllowAnonymous` or `@Public` on it or its class. A route that is open on purpose (a login, a health check, a webhook) takes `@Public('reason')`, which only records the intent and changes nothing at request time ([`@Public(reason)`](../http/13-policies.md#publicreason-a-route-that-is-open-on-purpose)). `@Public` next to a guard on the same route is reported as `HTTP006`.
3. **Add the manifest to CI** with a generator drift check and, if you want it, the PR comment from `manifest:diff` ([Manifest diff and CI](../manifest/diff-and-ci.md)).
4. **Switch to `require`** where the app is deployed, and ship the manifest with it ([Deploying a manifest-built app](../manifest/deploying.md)). Check the list in [What changes when you switch manifest mode on](../manifest/README.md#what-changes-when-you-switch-manifest-mode-on) first: request arguments are validated against derived schemas and query values are coerced.
5. **Replace hand-written `@Schema` duplicates** of your DTO types with [JSDoc constraint tags](../validation/09-dto-constraints-jsdoc.md) where they only repeated the TypeScript type.
6. **Generate a client** instead of writing one by hand ([`@spinajs/client`](../client/README.md)), and the OpenAPI or AsyncAPI document ([`@spinajs/openapi`](../openapi/README.md), [`@spinajs/asyncapi`](../asyncapi/README.md)).
7. **Move your tests** to `@spinajs/testing` ([Testing](../testing/README.md)).
8. **Type your DI keys** that have no class with `token<T>(key)` ([Typed tokens](../di/16-typed-tokens.md)).

## Release process

Releases are moving to [changesets](https://github.com/changesets/changesets) with one fixed group, `@spinajs/*`: every package gets the same version, bumped by the highest change level in the release. Automated releases are not enabled yet; the existing release scripts (`scripts/bump-all.mjs`, `scripts/publish-all.mjs`) and workflow are still in use until they are.

Once enabled, the intended flow is:

- Every pull request that changes behaviour adds a `.changeset/*.md` entry (`npx changeset`).
- A scheduled run (or a manual trigger) opens a "version packages" pull request that bumps versions, writes the changelogs and updates the lockfile.
- Merging that pull request publishes to npm and tags the release.
