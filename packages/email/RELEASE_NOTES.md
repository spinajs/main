# Release notes — email on authz-v3 (C9)

> Merged into the root `RELEASE_NOTES.md` for 3.0.0-rc.1.

- `IEmail.redact` lists secret values that the model or text carries (a reset token, a link holding it). Such a mail is never queued: `sendDeferred` refuses it. `EmailSent` carries no `Model` or `Content` for it. Errors that the service, the SMTP transport, the `email.send` and `template.render` Perf spans log or throw have the values replaced by `[redacted]` and no `cause` (design §23 SR-09).
- `EmailPasswordMailer` sends authn-local's reset and invite mails at once and never queues the secret. It is not registered by default, because `@spinajs/email` does not import `@spinajs/authn-local`: register it with `DI.register(EmailPasswordMailer).as(PasswordMailer)`. Config `email.password.{connection, from, lang, reset: { subject, template }, invite: { subject, template }}`; `connection` falls back to `email.defaultConnection`. Without a template it sends a plain-text mail. Template model: `Token`, `ResetUrl`, `ExpiresInMinutes`, `IsInvite`, `Name`, `Email`, `Purpose` (the 2.x names).
- `@spinajs/templates`: `IRenderOptions.redact` does the same for render errors.
- Warning: nodemailer's `logger` / `debug` options in a connection's `options` log whole message bodies, secrets included. Keep them off where reset or invite mails are sent.
- `EmailService.send` reads every attachment through its filesystem (`provider`, else `fs.defaultProvider`) before the transport, in the caller's async context: a filesystem guarded by authz-fs checks `fs:read` as the sending principal; an unguarded one reads as before. This holds for every transport, the black hole included. An unknown filesystem fails with `IOFail`. A refused read rethrows the `AccessDenied` unchanged (403 over http), is logged once, counts `email.send.failed`, and nothing is sent.
- `IEmailAttachement.file`: the local file the service read. The transport gets a copy of the mail whose attachments carry it and sends it without reading `path` again; the caller's mail is not changed, and a `file` the caller set is ignored. `email-smtp-transport` reads `path` itself only when `file` is absent (a sender used directly).
- `email.attachments.check` (default `true`). `false` leaves the reading to the transport, as in 2.x; a guarded filesystem then checks whoever runs the transport. The service drops a caller's `file` in both modes.
- `BlackHoleEmailSender` reads attachments that have no `file`, so development and tests fail where production would. `downloadAttachment` and `attachmentFile` are exported for other transports.
- `EmailSend` is `@Job({ runAs: 'initiator' })`: a deferred mail reads its attachments as the principal that queued it. A mail queued without a principal, or by a delegated or impersonating principal (authz-queue does not stamp those), runs unattended, so a guarded attachment is refused.
- Templates are still read by the transport, in the same context. Give template filesystems no `authz.fs` entry: reset and invite mails run without a user. The same holds for the filesystems of attachments that `users` lifecycle mails name (`users.email.*.attachments`): they are queued, often without a user behind them, so a guarded filesystem refuses them.
- A deferred mail whose attachment read is refused is retried like any failed job, although the answer stays the same.
